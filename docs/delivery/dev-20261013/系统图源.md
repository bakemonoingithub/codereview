## 图 1 系统逻辑架构

浏览器通过同源 HTTP 访问同一个 Spring Boot 进程。该进程同时提供 JAR 内的 static 前端。业务接口前缀为 `/api/v2`，在配置了 `agent.datasource.url` 之后注册，承载专项审查、Agent 只读工具和报告。应用库名为 `ai_code_review_agent`，迁移位于 `classpath:db/agent-migration`，历史表为 `agent_schema_history`，身份版本为 1。Git 宿主为 GitHub 或 Gitea，Gitea 差异和 Agent 检索使用 JGit bare 镜像。模型网关使用 OpenAI Chat 兼容的 `/chat/completions`。

## 图 2 专项审查与 Agent 分析

浏览器向 `/api/v2/review-tasks` 或 `/api/v2/agent-tasks` 提交，服务冻结快照后返回 202。专项按文件或差异调用模型并写入结果。Agent 原样回放历史，只读调用工具，只有 `submit_result` 才发布结果。命中预算不追加总结。进程再次启动时，尚未结束的排队或执行中任务标为失败，原因为 INTERRUPTED。

- PNG：[figures/review-sequence.png](figures/review-sequence.png)
- SVG：[figures/review-sequence.svg](figures/review-sequence.svg)
- Mermaid：[figures/review-sequence.mmd](figures/review-sequence.mmd)

```mermaid

  S --> R["PREPARING 后 RUNNING"]
  R --> SP["专项：拆分单元，JSON 调用，写入结果"]
  R --> AG["Agent：只读工具，submit_result 后发布<br/>不压缩上下文，命中预算即停止"]
  SP --> P["浏览器轮询至终态"]
  AG --> P
  P --> N["重启把尚未结束的 QUEUED/RUNNING 标为 INTERRUPTED"]
```

## 图 3 内网离线部署拓扑

GitHub Actions 用 Node 22 与 Java 17 构建 linux/amd64 镜像，并带上 mysql:8.0.36 组成离线包。内网 Compose 发布应用端口，默认 18080 转到容器 8080。MySQL 不发布宿主端口。应用库 `ai_code_review_agent` 由 `agent.datasource` 连接。交付模板生成的 `application.yml` 不含这一节，写入并重启后 `/api/v2` 才注册。应用镜像回退不撤销 `agent_schema_history`。
