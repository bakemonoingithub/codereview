## 术语表

本表解释正文中反复出现的概念。可先阅读，也可在遇到陌生术语时返回查阅。

| 术语 | 通俗说明 |
| --- | --- |
| 代码仓库 / Git / Gitea | 代码仓库集中保存项目文件及修改历史。Git 负责记录版本；Gitea 是通过网页管理 Git 仓库的服务，便于浏览代码和协作。 |
| 分支 branch | 同一项目的一条开发路线。不同分支可以分别开发和维护；分支名称不代表固定版本，继续提交后它指向的代码会变化。 |
| 提交 `commit` / SHA | 一次被 Git 保存的代码修改记录。SHA 是这次提交的编号，用它可以定位同一份代码版本；短 SHA 是完整编号的缩写。 |
| 差异 diff / 第一父提交 | diff 列出两个版本增加、删除或修改的内容。第一父提交是当前提交的第一个直接前序版本；合并提交还可能有其他父提交。 |
| 审查策略 / 分析器 | 策略是选好的分析方式、模型和参数组合；分析器是实际执行该类分析的程序。可以把它们理解为「检查方案」和「执行检查的工具」。 |
| 大模型 LLM / 模型名 | 大模型根据代码和要求生成分析意见。模型名是发送给网关的调用标识，必须与现场提供的名称一致；模型意见仍需人工复核。 |
| 提示词 Prompt | 发给模型的任务说明，例如检查重点、业务规则和回答格式。提示词不是待审查的代码，它用于告诉模型应怎样分析代码。 |
| AI 网关 / API 接口 | 接口是程序之间发送请求、接收结果的约定入口。AI 网关提供模型调用入口；系统向它发送模型名、提示词和代码材料，再读取回答。 |
| Token 认证令牌 | 调用网关或仓库时用来证明调用权限的凭据，作用类似钥匙。它不是模型名，也不是密码示例；保存配置和截图时需要保护它。 |
| 字符 / 模型 `token` | 字符是文本中的字、字母或符号；模型 `token` 是模型切分文本后使用的计量单位，二者没有固定换算比例。这里的 `token` 与认证令牌含义不同。 |
| JSON | 一种按字段组织数据的文本格式，便于程序读取。例如 `issues` 保存问题列表，`summary` 保存摘要；它与供人阅读的普通说明文字用途不同。 |
| Markdown | 用简单标记表示标题、列表和表格的文本格式，文件通常以 `.md` 结尾。本系统生成的报告使用这种格式，可以查看、保存和继续编辑。 |
| 配置快照 | 任务发起时保留的一份配置副本，用来说明当时采用的策略、模型和提示词。以后修改当前配置，不会自动改写这份历史副本。 |
| 结构摘要 / JavaParser | 结构摘要保留类名、字段、方法签名和依赖等代码骨架，减少送给模型的文本。JavaParser 是读取 Java 源码结构的工具；摘要不等同于完整方法实现。 |
| 耦合度 `coupling` | 描述代码之间相互依赖的程度。一个类或模块依赖较多，修改时可能影响更多地方；指标用于帮助定位复核重点，不能单独证明代码有缺陷。 |
| 扇入 `fanIn` / 扇出 `fanOut` | 扇入表示有多少其他类依赖当前类；扇出表示当前类依赖多少其他类。可理解为「多少地方会用到我」和「我会用到多少地方」。 |
| 模块指标 `Ca` / `Ce` / `I` | `Ca` 是依赖该模块的其他模块数，`Ce` 是该模块依赖的其他模块数。`I = Ce / (Ca + Ce)`，表示依赖向外的程度；这些值应结合实际分析范围理解。 |
| 设计模式 design pattern | 解决常见软件设计问题的一类组织方法，例如工厂模式、观察者模式。识别结果说明代码可能采用了哪种方法，还需要结合实际代码判断是否合适。 |
| merge-base / 三点比较 | merge-base 是两条开发路线共有的最近祖先版本。三点比较从这个共同起点计算目标路线的变化，用于观察分支从分叉后改了什么。 |
| 异步任务 / 任务池 / 队列 | 异步任务在后台执行，用户发起后可继续操作。任务池安排若干线程处理工作；队列存放等待处理的任务。进入队列不代表任务已经完成。 |
| 重试 / 超时 | 重试是在符合条件的失败后再次尝试请求；超时是等待或执行时间超过设定范围。二者用于处理异常，不代表一定能完成或得到正确分析结论。 |
| Docker / 镜像 / 容器 | Docker 用于运行打包好的应用。镜像是准备好的程序与运行环境；容器是镜像启动后的运行实例，可以把它们理解为「安装包」和「正在运行的程序」。 |
| JAR | Java 应用的打包文件。本项目把后端程序和构建后的前端静态资源一起装进 JAR，便于作为同一个应用发布和运行。 |
| MySQL / 持久化 | MySQL 是保存配置、审查记录和报告的数据库。持久化是把数据保存到数据库或磁盘，使它不只留在程序内存中；它不等同于备份。 |
| Flyway / 数据库迁移 | Flyway 按顺序执行有版本号的数据库修改脚本，例如新增字段或索引。迁移是调整数据库结构，不等同于备份恢复或应用镜像回退。 |

## 2 技术路线与能力范围

### 2.1 分析流程与设计依据

技术路线为「接入代码仓库 → 按策略选择分析器 → 确定性计算或模型调用 → 结果入库 → 人工复核与报告汇总」。

Java 依赖指标由程序计算；语义问题识别、设计模式判断和解释建议由模型生成。两类结果共同呈现，便于复核指标计算过程，并保留模型分析所需的上下文。

### 2.2 技术选型

| 层次 | 采用技术与作用 |
| --- | --- |
| 浏览器界面 | Vue 3、TypeScript、Vite、Ant Design Vue；Axios 调用 REST；ECharts 展示关系图；Markdown 与差异组件展示结果 |
| 服务端 | Java 17、Spring Boot 3.3.5、Spring MVC；业务服务负责配置、审查与报告；异步任务池执行分析 |
| 结构分析 | JavaParser 3.28.2，以 Java 17 语法级别抽取类型、显式 `import`、字段和方法签名 |
| Git 接入 | GitHub REST 与原文接口；Gitea REST 与 `.diff`；JGit 7.2 本地 bare 镜像辅助三点比较 |
| 模型接入 | Spring RestClient 调用 OpenAI 兼容 `chat/completions`；使用 `Bearer` 令牌，接收 JSON 或普通对话输出 |
| 数据层 | MySQL 8.0.36、MyBatis-Plus 3.5.7；Flyway V1 至 V7 管理数据库结构演进 |
| 构建与部署 | Node 22、pnpm 10.18.2、Maven 与 Java 17 三阶段 Docker 构建；JRE 17 jammy 运行；Linux amd64 离线包 |

### 2.3 五类策略及适用范围

| 策略 | 主要方法 | 输出与适用范围 |
| --- | --- | --- |
| 1 `llm-review` | 获取所选文件原文，按阈值分块后调用模型；可选多文件合并 | 单元问题、摘要及原始文本；适合源码规则与业务语义审查 |
| 2 `coupling` | 抽取 Java 结构，计算类依赖与包级模块指标，再尽力生成模型建议 | 扇入、扇出、强连通分量、模块指标 `Ca`、`Ce`、`I` 及建议 |
| 3 `design-pattern` | 将 Java 类型、字段、继承实现和方法签名摘要送入模型 | 固定十类设计模式、参与类、依据、置信度、误用判断和建议 |
| 4 `api-review` | 通过 POST 触发外部服务，按配置通过 GET 查询 `issues`，提供结果链接 | 外部问题或触发、查询错误；提供基础 API 适配，不负责完整流水线生命周期 |
| 5 `diff-review` | 读取单个提交相对第一父提交的变更，制备方法或 `hunk` 单元 | 变更问题、新侧行号、提交意图判断与原始结果；最多 50 个实际单元 |

设计模式识别的范围为单例、工厂、抽象工厂、建造者、观察者、策略、装饰器、适配器、代理和模板方法。系统没有覆盖全部 GoF 模式的承诺。

提交视图每次选择一个提交。需要处理多个提交时，可逐次审查，再汇总已有记录。

## 3 系统架构

![系统逻辑架构](figures/architecture.png)

图 1 系统逻辑架构

### 3.1 业务组件与模型调用

图 1 按运行职责划分浏览器、应用、数据库、Git 宿主和模型网关。`Controller` 提供统一 REST 入口；`Service` 校验并保存项目、策略、提示词版本和模型配置。

`ReviewExecutor` 与 `ReportExecutor` 在记录级任务池中分别执行审查和报告任务。`Analyzer` 按所选审查策略类型分发任务。文件审查、耦合建议、设计模式识别、diff 审查和报告生成调用模型，并记录任务执行情况。

### 3.2 仓库适配与本地镜像

`GitHostClientRegistry` 按仓库类型适配客户端；所内使用 Gitea，未知类型会显式报错。

所内部署的 Gitea 1.16.1 缺少代码比较接口，因此应用通过 JGit bare 镜像计算 merge-base 三点差异，并持久保存镜像中的代码，避免每次完整克隆后再计算。

### 3.3 前后端资源交付

Vue 构建资源进入后端 JAR 的 `static` 目录，页面和 API 由同一个应用端口提供。部署后通过 18080 端口访问。

## 4 执行过程与状态

![文件与提交差异审查时序](figures/review-sequence.png)

图 2 文件与提交差异审查时序

### 4.1 输入与记录创建

图 2 展示两类输入及共同的审查记录生命周期：用户选择分支和文件范围发起全文审查，或选择单个提交和变更文件发起 diff 审查。分析器负责制备审查材料，浏览器通过轮询获取状态；人工标记另行保存。

触发审查时，`ReviewService` 校验项目、策略和模型，保存分支、范围及策略、模型、提示词快照，并创建排队记录。

### 4.2 异步执行与结果保存

异步任务开始执行后，系统写入开始时间和进度。分析器获取原文或代码片段，制备代码单元，调用模型并聚合结果；结束时写入 `resultJson`、结束时间和终态。

界面耗时从任务实际开始到完成计算，不包含排队时间。

### 4.3 执行状态

| 状态值 | 界面含义与解释 |
| --- | --- |
| 0 | 排队中，任务尚未开始执行 |
| 1 | 执行中 |
| 2 | 成功，分析过程完成 |
| 3 | 失败，获取代码或审查时出错 |
| 4 | 部分成功，已有结果可读 |

## 5 AI 大模型设置方法

### 5.1 接入信息与推荐顺序

模型接入需要配置名称、接口地址、Token 和模型名。配置名称用于选择模型配置；模型名必须是网关接受的请求标识；Token 是请求使用的认证令牌。

推荐按以下顺序接入：

1. 取得现场网关根地址和模型标识。
2. 在「模型」页面新建配置。
3. 点击「验证」。
4. 执行一条小范围审查，核对 JSON 和实际输出。
5. 在审查策略中选择该模型。

创建或修改模型后，系统会尝试连通验证。验证失败时仍保留配置，并呈现失败状态。

### 5.2 验证范围与初始化限制

「验证」按钮发送 `max_tokens` 为 1 的极简请求，只证明该请求得到正常响应。首次启动时，从 YAML 建立的默认模型会直接标为成功，仍应人工点击「验证」并执行实际小范围审查。

### 5.3 参数位置与调用行为

| 参数 | 设置位置与当前行为 |
| --- | --- |
| `baseUrl`、`token`、`modelName` | 在模型界面设置，持久化到 `model_config`；策略通过 `modelConfigId` 绑定模型配置 |
| `deepseek.base-url`、`api-key`、`model` | YAML 默认模型初始化参数；模型表已有记录时不自动覆盖 |
| `temperature` | 正式调用固定为 0，页面不可调；不保证多次结果语义相同 |
| `response_format` | JSON 调用传 `json_object`；普通调用不传；不是 JSON Schema 约束 |
| `messages` | 正式请求为 `system` 与 `user`；`ping` 仅发送 `user` 内容 |
| `max_tokens` | 仅 `ping` 设置为 1；正式审查与报告未设置；界面无该字段 |
| `connect-timeout-ms` | YAML，默认 10000 毫秒；非正值回退到默认值 |
| `read-timeout-ms` | YAML，默认 300000 毫秒；非正值回退到默认值 |

JSON 调用的请求结构如下，`Authorization` 使用 `Bearer` 令牌。图源和文档不保存真实令牌。

```json
{
  "model": "<现场模型标识>",
  "temperature": 0,
  "response_format": {"type": "json_object"},
  "messages": [
    {"role": "system", "content": "角色与格式要求"},
    {"role": "user", "content": "分析模板 关注点 输入材料"}
  ]
}
```

### 5.4 自定义提示词与结果形式

自定义提示词对不同策略的影响如下：

- 文件 LLM、耦合和设计模式策略绑定非空提示词后，改用普通对话并保存自由文本；文件 LLM 的结构化 `issues` 可能为空。
- diff 审查将提示词作为固定 JSON 模板内的关注点，不替换输出协议。
- 综合报告使用普通对话生成 Markdown。

## 6 分析方法与输入边界

### 6.1 全文审查的分块与合并

全文审查默认按文件生成单元。超过阈值 `chunk-max-chars=140000`（单位为字符）时，优先按方法或构造器边界切分；无法按该边界切分时，改为按行切分。

多文件合并审查将材料放入一次调用请求。超过阈值时直接失败，不再自动拆分。

### 6.2 提交差异的基线与单元限制

diff 审查以第一父提交到当前提交为比较基线，`merge` 提交也按第一父提交比较。

Java 变更尽量补全新侧方法体，并按变更行窗口裁剪；无法制备时回退到 `hunk` 或全文。默认窗口为 60 行，内部最小值为 10 行。

单个文件可能形成多个单元。实际单元数超过 50 时，任务会失败并要求分批。前端「预估单元数」实际是可审查文件数，不能据此确定真实调用次数。

### 6.3 耦合度的材料范围与指标

依赖图中的边来自所选源码中非静态、非通配的显式 `import`，目标类也必须位于当前抽取集合内。系统未使用 `symbol-solver`，结果不覆盖同包引用、反射、运行时注入和完整调用关系。

系统只抽取顶层类型；Lombok 生成的方法和内部匿名类型不构成完整结构材料。原文获取失败或解析失败的文件可能被跳过，因此「未发现循环」仅适用于成功制备的范围。

类级高耦合条件为 `fanOut` 大于策略 `threshold`，默认阈值为 10。循环检测采用 Tarjan 强连通分量，表示依赖图中存在环，不证明运行时存在递归。

包级模块按共同包根的下一段聚合：`Ca` 为依赖该模块的去重模块数，`Ce` 为该模块依赖的去重模块数，`I = Ce / (Ca + Ce)`。结果保留两位小数；无边时 `I` 为 0。模块高耦合条件固定为 `Ce` 大于 3 且 `I` 不小于 0.8，与类级阈值分别解释。

### 6.4 设计模式识别的解释范围

设计模式识别主要依赖结构摘要，缺少所有方法体的完整业务上下文。置信度是模型输出值，不能作为经校准的概率使用。

### 6.5 外部 API 分析的生命周期

外部 API 分析支持触发与一次查询，未实现持续等待 SonarQube 等外部任务完成的统一轮询。应结合外部结果链接核对原始产物。

## 7 调度、数据与可靠性

### 7.1 并发、重试与时间预算

| 参数或机制 | 当前配置与约束 |
| --- | --- |
| 记录级任务池 | `core` 2、`max` 4、`queue` 100；审查与报告共享 |
| 单元级任务池 | `review.concurrency` 默认 4；`core` 与 `max` 相同，`queue` 1000；用于全文与 diff 单元 |
| 自动重试 | `retry-max` 默认 3；首次调用加 3 次重试，最多调用 4 次；默认退避间隔为 1、2、4 秒 |
| 可重试错误 | 网络超时、网络访问错误、5xx、403、429；无令牌、401 和确定性解析错误不自动重试 |
| 任务预算 | `task-timeout-minutes` 默认 50；在提交后续任务前协作检查期限，不是任务总耗时的硬上限 |
| 报告聚合预算 | 最终 `user prompt` 默认 140000 字符；每条聚合材料默认 20000 字符 |
| 结果写入 | `result_json` 与报告正文使用 `MEDIUMTEXT`；错误原因使用 `VARCHAR` 1000，并限制长度后截断 |

单元重试循环用于文件 LLM 和 diff；耦合建议、设计模式识别及报告没有同一套自动重试机制。

系统不会持续根据 `deadline` 中断已经提交的单元和重试循环；队列等待也会增加总耗时。因此，默认 50 分钟不能作为「审查加报告一小时必定完成」的证明。实际业务耗时需要在指定环境和指定样本上测量。

### 7.2 数据库结构与结果保存

数据库包括 `sys_user`、`prompt`、`prompt_version`、`model_config`、`review_strategy`、`project`、`review_record`、`report`、`report_record` 和 `issue_mark` 十张应用表。主键由应用分配，`Long` 向浏览器序列化为字符串。多数业务对象采用逻辑删除；关联由服务维护，没有物理外键。

Flyway V1 至 V7 保持已有迁移不可改写，通过后续迁移增加索引、时间字段和大文本容量。

结果超过 1 MiB 时，系统告警而不自动截断。保存失败时，系统尝试写入长度受限的错误信息并结束执行态；数据库完全不可用时，仍可能只能记录日志。

### 7.3 报告材料裁剪与范围核对

报告先对所选记录去重，再聚合材料。材料过大时，会截断单条材料或停止纳入后续条目；原始记录仍保存在数据库中。

正式报告应检查材料是否被裁剪，并核对选择范围、SHA 和策略快照。

### 7.4 缓存与聚合的已知风险

Git Caffeine 缓存默认保存 200 条提交详情和 500 条原文，写入后 30 分钟过期。结构分析材料缓存没有 TTL 与容量配置，缓存键缺少仓库、宿主和分支维度；长时间处理多个仓库时，应关注材料隔离风险。

读取报告聚合材料的查询结果没有包含 `status`。失败记录带有非空旧结果时，仍可能被纳入报告。当前 diff 聚合名称会使用默认 `llm-review` 标签，复核应以 `type` 5 快照和 `commit` 字段为准。
