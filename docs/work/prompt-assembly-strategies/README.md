# PAS 提示词组装职责拆分工作计划

日期：2026-11-02。源码起点：`dev`，`67d411e150deb5299bb9dd1cc11f746672ae9915`；规划前工作区无未提交内容。负责人要求先落盘计划，后续在本会话实施，在其他会话执行独立等价验证。PAS-01 已完成实施与交接，PAS-02 独立验证已完成，详见 [交接记录](handoff.md)及[独立验证报告](verification-report.md)。

## 1. 目标与依据

保留 `PromptAssemblyService` 作为统一门面，将不同场景的组装流程委托给策略，将消息封装、材料格式及计量等重复逻辑交给公共组件。改善职责边界，保持模型实际请求、容量判断和执行行为不变。

业务规则以[业务契约](../agent-redesign/business-contract.md)为准；既有正文抽取及固定请求来源见 [PAR 计划](../prompt-assembly-refactor/README.md)和[基线说明](../prompt-assembly-refactor/baseline.md)。输出契约与语义关联继续遵循 [BRC 维护索引](../backend-rule-consolidation/maintenance-map.md)，不重开已完成的 PAR／BRC 工作包。

## 2. 范围与结构

### 2.1 职责分配

以下组件名为建议名，实施时可调整；职责和类型约束保持。

| 层次 | 组件 | 职责 |
| --- | --- | --- |
| 门面 | PromptAssemblyService | 保留现有对外方法，委托相应策略或渲染组件，不承担场景正文编排 |
| 场景策略 | SpecialistPromptStrategy | 问题文件／差异、模式、耦合共用场景结构；保持目标材料前置检查 |
| 场景策略 | ReportPromptStrategy | 报告任务、规则、冻结事实的原有顺序 |
| 场景策略 | AgentPromptStrategy | 要求、范围、固定版本、比较关系、指导、参考线索、历史消息 |
| 场景策略 | ToolCheckPromptStrategy | 工具验证首轮及回放轮的消息构造 |
| 验证流程 | 连通验证组装 | 明确承接 VALIDATION，保留当前普通消息结构；不误分配给只接受专项的策略 |
| 公共封装 | PromptMessageFactory 等 | 消息封装、字节统计、估算字段生成；显式保留普通消息与工具历史的既有计量差异 |
| 公共渲染 | PromptSections／PromptSystemRenderer 等 | 材料来源与行号、截断、模板选择和契约片段注入；有实际复用再提取 |
| 纠正渲染 | AgentCorrectionRenderer 等 | 类型化事件到模板正文；触发条件、角色及插入位置仍归执行器 |

保留 `PromptInput` 和 `AgentPromptInput` 的类型边界。专项和报告可以采用同输入类型的策略接口；Agent 与工具验证使用各自类型化方法，不为统一接口改用 `Object`、未约束的 Map 或大包可空参数。策略选择可使用显式委托或小型映射，不引入动态插件注册框架。

### 2.2 保留的接口与行为

- 保留 `assemble`、`assembleAgent`、`assembleToolCheck`、`assembleToolCheckFollowUp`、`correction`、`systemPrompt`、`protocolBody` 的对外签名；核对无参构造、测试及手工装配入口，避免只在 Spring 环境可用。
- 核对包内静态工具方法及常量的直接使用。内部迁移可调整测试接缝，不删除外部有效入口来迁就新结构。
- 模板仍由 `PromptTemplateRegistry` 加载和单次替换；契约仍来自 `SpecialistOutputContracts`、`AgentSubmissionContract`、`ReportCitationContract`。
- 工具能力仍经 `OpenAiChatToolAdapter` 转换；保留协议版本、工具 Schema 版本和现有估算方法标识。
- 普通空值判断、可选段落判断、有限模板映射继续使用条件判断，不按每个字段新增策略类。

### 2.3 不纳入本次

不调整提示词文案、段落、换行、限额、优先级、工具定义、输出契约、模型请求参数；不修改任务执行循环、重试、预算及容量算法；不迁移数据库、不修改前端、不新增运行依赖。`AgentDatabase` 的历史注释清理另行处理，不随本工作包夹带。

## 4. 本会话实施顺序

1. 固定基准：重新核对分支和未提交内容，记录不可变的改造前源码。盘点所有门面入口及构造方式，重点核对专项分片估算、报告、模型验证和 Agent 工具往返。
2. 对已有请求和工具基线计算 SHA-256，保存文件清单；在原实现执行核心基线检查。补充覆盖需要的输入先在原实现运行，保存期望来源。正式独立验证尚未开始，此处只建立改造前依据。
3. 实施迁移：先提取公共封装及渲染，再迁移专项、报告、Agent、工具验证；显式安排 VALIDATION。保持每次迁移可编译，不同时修改正文或契约。
4. 保留无参构造与正常应用装配的一致行为，核对模板何时加载及失败是否仍可阻止初始化，避免延迟到真实调用才报错。
5. 执行编译和改动直接相关的基本检查，处理实现错误。必要时调整仅绑定旧内部方法的测试，但不改冻结期望、业务断言及比较强度。本会话检查不替代 PAS-02 的独立结论。
6. 更新迁移涉及的维护索引、源码关联注释及当前文档；填写交接记录，冻结候选版本。PAS-01 完成后停止功能扩展，PAS-02 保持待验证。

## 5. 跨会话交接

- 改造前完整提交 SHA、候选完整提交 SHA；若没有提交，提供相对基准的完整补丁、新增文件、文件哈希清单和可复现的候选副本，不要求为验证自动提交或推送。
- 涉及的生产文件、测试文件、资源文件及文档；门面方法到策略的对应表，构造／依赖注入方式。
- 原有两份冻结基线的哈希、模板文件清单及哈希；新增边界样本、旧实现输出和捕获方式。
- 已执行检查、命令、环境、通过／失败／跳过数、报告位置及未处理问题。没有运行的项目明确写「未执行」。
- PAS-02 读取入口为 [verification.md](verification.md)。验证期间实施会话不修改被验证文件；修复后重新冻结候选版本，由验证会话确认需复跑范围。

验证应优先使用隔离副本和独立构建目录；共享主工作树保持已有内容，不切换或清理他人正在编辑的文件。验证会话可补充独立测试和记录；生产修复交回实施会话，避免边改边验导致版本不明。

## 6. 关闭条件

PAS-01 完成只代表实施可交接；PAS-02 未完成前不得写「等价验证通过」或关闭工作包。请求及计量等价、场景行为回归、构造及模板初始化、资源打包和后端全量检查均按验证手册完成；失败、异常和跳过有逐项解释。最终状态绑定实际验证的候选版本。

本工作包不要求真实模型、现有数据库、业务服务启停、页面或部署验收，不把固定样本通过扩大为模型效果、任意输入或真实环境的完全等价证明。
