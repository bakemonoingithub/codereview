# P30.4 固定版本读取与有界缓存

状态：P30.4 完成（2026-10-20，Asia/Taipei）。依据 [P30.1](p30-1-reuse-diff.md) 第 6.3、6.6 节与 ROADMAP P30.4、[共用设计](../p29/shared-design.md) 4.2、[专项设计](../p29/specialist-design.md) 3。本项不做 Agent 搜索工具，也不开放任意命令执行。

## 2. 行为

- **只认完整 40 位 SHA**：短 SHA 与分支名在入口即拒绝（`VALIDATION_FAILED`）。分支名会移动，无法证明读到的就是任务发起时的版本。
- **路径清单**：按路径排序，`blob` 才标 `reviewable`；目录条目不因路径像源码而变成可审查文件。
- **文件读取**：返回正文、SHA-256、UTF-8 字节数与行数。含 NUL 的文件判为二进制；超过 4 MiB 判为不可读；两者都失败而不是截断后冒充完整文件。
- **行范围**：闭区间，行号从 1 开始；`hasMore` 表示该文件后面还有内容，返回的行号仍然是原文件行号。
- **差异两侧**：目标提交取第一父提交作为 before；新增文件没有 before，删除文件没有 after，根提交明确标记缺失。某一侧读取失败只让该侧标 `beforeMissing`，另一侧照常返回。
- **错误分类**：路径/版本格式错误是 400；宿主未接入、令牌被拒绝、传输失败是 422 `REPO_UNREACHABLE`；二进制、超大、不可读文件是 422 `FILE_NOT_READABLE`；提交里没有该文件是 404。
- **不做传输重试**：本层只读取与分类，重试由宿主客户端和 P30.5 的统一调用负责，避免同一请求在多层重复放大额度。

## 3. 缓存

- 文件缓存按 `(项目, 项目 revision, SHA, 路径)` 组成键，权重上限 128 MiB、写入后 30 分钟过期；路径清单缓存 256 个版本、10 分钟过期。
- 键里带项目 revision：更换令牌后 revision 增加，旧内容自然失联，不会继续用旧凭据读到的东西。
- 键里带 SHA：分支移动、同名文件在新提交变化都不会命中旧内容；不存在"按分支名缓存"的路径。
- 只缓存成功结果；二进制、超大、读取失败不进缓存，避免把暂态失败固化为永久缺失。
