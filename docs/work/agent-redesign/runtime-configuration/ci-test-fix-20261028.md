## 6. 关闭应用环境变量配置

负责人要求「关闭从环境变量里读取配置，就按照我在配置文件里写的」。当前规则已纳入[CFG-B07](../business-contract.md#10-运行配置外置2026-10-26)及[配置规范](specification.md#1-加载生效与兼容)，本节取代第 5 节尚未提交的临时兼容方案。

### 实现与使用变化

- 新增 `FileConfigurationEnvironmentPostProcessor`，通过 `META-INF/spring.factories` 注册，在 Spring 内置系统环境处理、JSON 处理及 ConfigData 加载前移除系统环境属性来源。正式启动与 `--check-config` 自动使用相同规则；直接配置校验入口也执行相同移除，覆盖测试及嵌入式上下文。
- 环境变量不再覆盖应用参数，也不参与文件选择、profile、`@ConfigurationProperties`、`@Value` 与占位符解析。删除宿主变量预检、反射键表及逐项豁免逻辑，文件／命令行中的未知键、类型及范围检查保留。
- 显式命令行和 Java `-D` 系统属性仍可用，保留现有 `--spring.config.location` 启动入口及检查方式；标准部署不追加业务覆盖。进程操作系统环境仍存在，JVM、脚本与 Git 子进程的正常执行不受 Spring 属性来源移除影响。
- 三份应用样例改为明确的数据库值、空兜底令牌及目录值，不再依赖 `${DB_URL}`／`${GITHUB_TOKEN:}` 等环境引用。容器模板仍由脚本首次渲染数据库值；通用样例使用示例地址、账号与 `CHANGE_ME`，实际部署前必须填写真实值。
- Compose 与部署静态检查不再注入应用令牌及镜像目录，`.env.example` 与脚本导出表移除这些旧项。数据库初始化、端口、资源和 JVM 参数仍由部署 `.env`／Compose 管理，应用配置在 YAML 中填写。
- 旧部署升级须手工将已知环境引用改成实际值；前置体检发现六类旧引用时停止，不打印值。脚本不复制旧 `.env` 凭据，也不覆盖实际 YAML。手册已说明新规则、权限及迁移步骤。

本机被 Git 忽略的 `backend/src/main/resources/application.yml` 中，已知旧令牌与目录环境引用改为明确空值，数据库及其他已有参数保留；未重启服务。公开样例与代码不包含实际凭据。
