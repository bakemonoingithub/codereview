## 2. 配置归属与生效方式

| 配置归属 | 目标位置 | 内容 | 生效方式 |
| --- | --- | --- | --- |
| 应用运行参数 | 部署目录 `config/application.yml` | 数据库、Git、模型调用资源、任务、Agent、专项、报告、公开前端参数 | 修改后重启应用；涉及任务预算的配置用于重启后新建任务 |
| 部署环境参数 | 部署目录 `.env` 和 Compose | 端口映射、JVM／容器内存、日志、网络、持久化目录、凭据环境变量 | 重新创建受影响容器；只改 `.env` 后执行容器 restart 不保证生效 |
| 业务配置 | 现有管理界面及数据库 | 模型网关、模型名称与窗口、项目仓库与分支、提示词及版本 | 沿用现有修订、验证和任务冻结规则，不被文件静默覆盖 |

不新增配置管理页面，不引入热更新、配置中心或多节点调度。前端只读取明确允许公开的字段，不读取数据库、模型或仓库凭据。

统一文件是应用运行参数的入口，不将业务数据库和容器参数强行合并到同一 YAML。开发环境与部署环境使用相同键名和默认值；环境差异由外置文件和环境变量提供。

### 3.3 部署参数

沿用 `.env` 的端口、绑定地址、JVM 参数、应用／数据库内存、MySQL 缓冲池及容器网段配置。将日志滚动大小／数量、MySQL 最大连接数和需要迁移的数据挂载位置补为有说明的参数。镜像版本继续由发布流程管理。

连接池最大连接数须结合其他数据库用户预算评估；JVM 堆上限不能占满容器内存，应为线程、直接内存、Git 和运行时预留空间。具体部署值在目标环境验收时填写，不在计划中臆定。

## 4. 实现规则

### 4.1 加载与配置来源

1. 生产启动入口显式指定外置配置位置，文件缺失或无法解析时启动失败；镜像中只保留无秘密的默认值／样例，不包含本机实际 `application.yml`。
2. 配置规范列出键名、类型、单位、默认值、允许范围、功能、敏感性、生效时机和源码入口。优先使用既有 `agent.*`／`git.*` 命名，避免重命名造成旧配置静默失效。
3. 明确外置文件、环境变量和启动参数的覆盖顺序，并通过启动测试验证。标准部署入口避免追加隐藏业务覆盖；实际覆盖项仅输出脱敏摘要。
4. `.env` 中凭据通过应用环境变量提供，YAML 使用占位引用。检查部署脚本已有“首次渲染后不覆盖”的行为，避免运维修改 `.env` 后误认为已经更新渲染过的 YAML。
5. 自有配置命名空间拒绝未知键或给出足以阻止误部署的检查结果；不对 Spring 全部标准配置实施自定义封闭白名单。
6. 外置文件校验提供部署前检查路径；正式启动也校验。自有参数校验应在调度任务和调用外部模型之前完成，并尽量前置到数据库迁移之前。

### 4.2 参数校验

校验正数、单位、比例范围、默认值不大于最大值、最小空闲连接不大于最大连接数、单任务并发不大于全局并发、单材料上限小于工具 envelope 上限。错误信息包含键名、约束和非敏感原因，不输出凭据。

Agent 网络尝试预算不得高于公共调用限额；总期限、单次超时、模型输出上限和安全余量共同约束实际请求。模型窗口来自数据库，相关容量组合在选定模型／创建任务时检查，不能只依赖启动校验。工具容量限制变动后，仍须给分页和精确读取出口，防止重复截断循环。

所有默认值尽量来自一个类型化配置来源。保留代码默认值用于缺省参数，文档和样例通过一致性检查避免漂移；不复制多套数值到执行器、工具 schema 和前端。

### 4.3 任务快照与工具准入

创建任务时冻结影响执行语义的预算、工具限制和容量策略。执行器、工具定义、提示词、工具参数校验、进度展示都使用同一份有效配置；连接池、缓存容量等进程资源参数使用本次启动值。

工具 schema／行为配置变化纳入工具协议指纹及模型准入匹配检查。只改缓存和进程资源参数不应使模型准入失效；改变工具约束后，旧验证记录不能被静默视为仍匹配。新任务要求匹配当前工具能力的验证；历史任务详情和调用记录仍能读取。

快照版本与旧快照读取策略在 CFG-02 定稿：新增字段明确缺省来源，读取旧任务采用其历史版本的默认解释，不能用新部署值改写历史含义。配置摘要不含数据库、仓库或模型凭据。

依据预算实验，核对累计资源保险计算与网络次数、窗口比例及输出预留之间的关系；修改预算后同步计算，不能仅替换常量而保留旧额度。

重启不恢复中断任务。维护前等待任务完成或按现有取消流程结束；异常重启后的遗留任务和报告沿用中断收敛。配置回退也不会把已终止任务恢复为运行中。

### 4.4 前端运行配置

新增只读公开配置端点，拟为 `GET /api/v2/runtime-config`。只返回版本、应用标题、业务 API 基址、请求超时和各类轮询间隔等白名单字段。配置响应不缓存，前端启动时先加载，再创建业务请求客户端和启动轮询。

配置入口使用与部署基路径兼容的同源相对地址，不依赖尚未加载的业务 API 基址，也不依赖编译时 `VITE_*`。本期默认同源部署；跨源网关不在此次兼容承诺内。明确区分公开配置端点的引导地址与业务 API 地址，避免循环依赖。

加载失败、字段非法或版本不兼容时，停止发起业务请求并显示可重试提示；不静默恢复编译时配置。统一标题使用点和三类详情轮询，历史未使用页面不扩大改造范围。

应用重启后，已打开的页面需刷新才能读取新前端配置。运维说明明确这一点，不声称现有页面自动热更新。加载失败／重试属于界面行为变化，按项目约定先给最小独立 HTML 原型确认，再实施框架界面。

### 4.5 模板、部署和回退

同步后端样例、容器模板、首次部署渲染脚本、环境检查、健康检查和运维手册。按当前单库启动路径移除模板中的旧 `spring.datasource.*`、旧 Flyway 链、`deepseek.*`、`review.*`、旧 `report.*` 等误导入口；不删除旧源码或实际数据库。

`agent.datasource.migration-location/history-table` 保留现有兼容读取，但列为内部固定项；运维普通配置不鼓励修改迁移链。模型与项目数据库记录不由启动文件覆盖。

应用参数变更前备份外置配置，校验通过后重启并核对脱敏摘要和健康检查；失败时恢复上一份配置并重启。部署参数变更通过 Compose 重新创建受影响容器。首次程序升级保留上一镜像和与其兼容的配置；若实现引入数据库迁移，另列兼容与回退方案，不能假设回退镜像即可回退数据结构。

| CFG-A07 | 工具限额与准入 | schema、描述、校验和执行取值一致；修改行为配置后旧准入不误用；仅改缓存不导致无谓重新验证 |
| CFG-A08 | 工具分页与材料 | 返回大小、行号、截断提示、游标和引用范围一致；小容量配置不能产生无限重复页 |
| CFG-A09 | 仓库与数据库 | HTTP／镜像超时、文件限制、白名单及连接池配置接入实际组件；误连库保护继续生效 |
| CFG-A10 | 并发与积压 | 全局／任务／文件并发共同生效；任务与报告队列满时明确终止或拒绝，不遗留永久排队任务 |
| CFG-A11 | 前端无重编译 | 同一静态资源，重启后刷新页面取得新标题、超时和轮询间隔；旧页面刷新要求明确 |
| CFG-A12 | 前端配置异常 | 加载失败可重试；迟到响应及非法配置不启动错误请求；公开响应没有秘密；负责人确认 PC 状态 |
| CFG-A13 | 容器参数 | 修改 `.env` 后重新创建容器，端口／环境／资源实际更新；仅 restart 的适用边界写入说明 |
| CFG-A14 | 模板与业务配置 | 开发／部署样例一致；旧配置不误导；升级不覆盖现有模型、项目、提示词或运维配置 |
| CFG-A15 | 中断与回退 | 隔离环境验证遗留任务／报告收敛、配置回退及兼容版本启动；不修改历史结果或自动续跑 |
| CFG-A16 | 三类业务实际使用 | 专项、Agent、混合来源报告各完成代表样本，核对生效参数和实际请求；真实调用与替身测试分别记录 |
| CFG-A17 | 目标内网 | 验证 Gitea 地址／凭据、Git 程序、冷镜像、大仓库、目录权限及 Windows 长路径或目标 Linux 挂载；缺少环境则明确未验证 |

工程检查按变更模块选择，覆盖配置绑定、启动、快照、工具、队列及前端引导。涉及公共调用、构建入口与部署脚本时再执行相应集成检查，不用仅构建成功替代重启生效证明。
