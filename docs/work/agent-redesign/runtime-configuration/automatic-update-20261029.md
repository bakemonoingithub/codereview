# 自动升级入口交付记录

日期：2026-10-29。负责人确认自动升级方案并授权实施：传入新包目录、原部署目录和明确目标版本，支持只读检查与可选旧镜像导出。授权范围为脚本、手册及工程检查；本轮不操作真实数据库或现有服务，不构建、发布离线包。

## 1. 实现与入口

新增 [update.sh](../../../../deploy/scripts/update.sh)，必须从新包运行。参数、前置条件及运行示例以[系统运维手册第 4.2 节](../../../../deploy/系统运维手册.md#42-自动升级入口)为准；保留手动升级流程及此前逐命令注释。

脚本复用 Shell、Docker、Compose 与容器内的 MySQL 客户端，不新增宿主机或镜像运行依赖，语法按 Bash 4.2 编写。原 `.env` 提供连接凭据，实际 YAML 不自动合并或覆盖。

停止应用前核对目录分离、符号链接、镜像包及校验清单、MySQL 服务配置、应用挂载、现有容器的实际挂载、数据库身份和未完成任务。使用新包的前置体检检查原部署环境；正常模式先导入指定应用镜像，再用目标镜像对原 YAML 执行不联网的静态配置检查。新 Compose 在原部署目录上下文展开，只校验而不打印凭据。

只读模式不导入镜像、不停止服务、不创建升级锁或封存文件、不复制交付文件。目标镜像须已在本机；否则失败退出，不把尚未完成的新镜像配置检查记作通过。配置检查会短暂创建并删除不联网的检查容器。

进入维护后，停止应用并再次检查任务，防止检查期间新任务进入；有在途任务则退出并保留停止状态。独立封存数据库、`.env`、实际 YAML、Compose、旧脚本、旧镜像名称及 ID、目标镜像信息和关键表计数。旧镜像按 ID 增加独立保留标签；可选导出使用该标签。导出及压缩校验失败时停止，不更新交付文件。

复制范围为镜像文件、脚本、Compose、配置模板、手册及包内运维附件。保留原 `data/`、实际 YAML、`.env` 和备份；部署脚本会按原有规则更新 `.env` 中的版本等部署参数。部署后核对目标镜像 ID、原挂载、实际 YAML、业务健康接口、迁移失败记录及项目／模型／提示词／审查／报告表的记录数。

## 2. 配套调整

- [backup.sh](../../../../deploy/scripts/backup.sh) 新增 `--install` 和 `--output-dir`。默认调用继续使用原部署目录的 `backups/` 和 7 天保留规则；指定独立封存目录时不执行过期清理。`.env` 备份或权限保护失败时返回失败。
- [preflight.sh](../../../../deploy/scripts/preflight.sh) 新增 `--install`，供新包只读检查原部署环境；默认入口不变。
- [deploy.sh](../../../../deploy/scripts/deploy.sh) 新增 `--exact-tag`，要求明确版本，仅导入该版本应用镜像，不导入 MySQL 或旧应用镜像，目标镜像缺失时禁止自动选择其他版本。自动升级入口使用此模式及既有 `--yes`。更新 `.env` 中的镜像版本或网段后同步进程环境，避免 Compose 优先读取先前导出的旧值；自动升级替身检查实际启动时的 `APP_TAG`。
- [Release 工作流](../../../../.github/workflows/release.yml) 加入语法、自动升级及既有部署替身检查，并检查离线包包含 `update.sh`。实际远端流水线尚未执行。

## 4. 限制与接续

只支持当前新路线的标准绑定挂载，不自动转换九月旧库、不迁移数据库数据目录、不升级 MySQL 镜像，也不自动修改已发布迁移或执行清理。MySQL 服务配置和应用挂载变化时须另行评估。

升级前须暂停新任务提交，并确保没有其他应用实例或外部数据库写入者。脚本锁只协调本入口，不阻止人工 Docker 操作或外部写入。进入维护后的任何失败均尝试停止应用并保留现场，不自动恢复配置、数据库或镜像。强制终止／断电可能遗留锁，需人工确认无升级进程后处理。

本次未验证真实内网部署、Docker 挂载及配置展开、真实 SQL 备份／迁移、数据库恢复、历史记录可读性或新业务流程。压缩校验、镜像 ID 和表记录数不代表数据内容及恢复能力已验证；迁移若预期新增或删除关键业务表记录，计数检查也会要求人工核对。基础检查通过后仍须完成手册要求的业务验收。备份恢复演练沿用既有要求，不由本入口自动执行。

本次完成自动升级入口的工程交付，不据此关闭 CFG-06／07 或其他工作包的实际环境验收项。
