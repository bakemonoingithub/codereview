## 2. 参数与执行行为

- `agent.model.transport-retries` 接受 0–10 次额外重试，默认仍为 1。公共调用记录每次真实网络尝试，仍受实际任务额度和期限约束。
- 新增 `retry-max-millis`、`retry-multiplier`、`retry-jitter-ratio`、`retry-check-millis`，结合已有 `retry-base-millis` 控制本地递增等待、随机错峰和取消检查。`Retry-After` 支持非负秒数与 HTTP 日期，适用于 429 和 5xx；不再最多只等 3 秒。网关要求超过剩余期限时结束，不提前再次请求。
- 新 Agent 的 `invocationPolicy.retryBackoff` 冻结完整等待策略；每轮按剩余网络预算裁剪重试次数时保留其他冻结字段。旧快照缺少新节点时使用历史固定等待与无随机变化，不读取新部署值；历史缺省常量继续作为兼容解释保留。
- 新增 `connectivity-validation-timeout-seconds`、`tool-validation-timeout-seconds`、`tool-validation-output-tokens`，替换普通验证 1 分钟、工具验证每轮 2 分钟与 1024 输出的执行常量。保留相同代码默认值，运维可以覆盖。已有 `probe-*` 仍属于轻量 ModelProbe，不冒充普通管理界面的验证期限。
- 新增 `app.ui.model-validation-timeout-millis`、`agent-validation-timeout-millis`；浏览器仅在对应验证接口使用长等待。公开配置明确添加两个白名单字段，仍为 version 1；旧七字段响应回退到其普通请求超时，非法新增字段拒绝加载。
- 启动检查新增重试范围、退避组合及浏览器／后端验证期限关系校验，在业务组件及数据库构造前执行。

完整键表、默认值与范围见[配置规范](specification.md)。代码默认值与内网试运行建议值分别维护，不将未实测的建议称为最优值。

## 3. 模板与部署脚本

容器模板已覆盖全部运行参数并移除旧路线数据源和旧模型配置入口；通用参考与后端样例使用同一组规范键。容器模板使用部署脚本替换数据库占位符，通用样例使用 DB_URL／DB_USER／DB_PASSWORD，手册说明两者的区别。

内网模板建议：公共／Agent 单次响应各 600 秒、专项／Agent 总期限各 120 分钟、报告 30 分钟、额外重试 3 次、初始等待 3 秒、增长倍数 2、局部上限 30 秒、随机比例 0.2、模型全局／单任务并发 2／1。Agent 网络预算 192 次、公共上限 200 次，为 48 轮各最多 4 次尝试提供次数空间；总期限可能提前结束，不能保证耗尽全部轮次。

普通验证总期限为 600 秒、工具验证每轮 1200 秒；浏览器分别等待 900000／2700000 毫秒。输出、轮数、工具材料限制和安全余量继续保留原基线。`.env.example` 在 4g 应用上限中建议 Java 最大堆 3g，保留非堆、线程和 Git 空间；仍需负载验证，不覆盖已有正式 `.env`。

Docker 入口明确读取外置 YAML，并补入 Agent 搜索所需的 Git 程序，构建时检查 `git --version`。部署脚本在数据库启动前，用新镜像、实际 YAML 及相同的相关环境变量执行 `--check-config`；检查进程不连接数据库、模型或仓库。已有运行应用须先处理任务并停止后再升级。

升级失败不再自动回退镜像；脚本尝试停止应用并保留数据库现场。只回退镜像须指定明确版本并声明已确认结构与配置兼容；数据库不就绪或备份失败时停止。备份脚本缺少业务库时失败，只有不存在的兼容库可以跳过。

发布流程检查配置键及三份手册存在，并排除开发自测脚本。尚未执行完整镜像构建或公开发布，不将这些静态门槛当作打包通过证据。
