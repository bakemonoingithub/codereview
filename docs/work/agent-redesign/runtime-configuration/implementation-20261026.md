## 2. 关键实现与修复

- 保留既有配置键，新增类型化预算、工具限额、仓库、Git HTTP／宿主和前端参数。参数在数据库与任务线程池构造前校验；未知自有键、环境变量拼写错误和非法组合明确失败。`GIT_PAGER` 等非应用环境变量继续可用。错误只报告键名和约束。
- `--check-config` 使用相同配置加载和覆盖规则，只建立静态校验上下文；不扫描业务组件、不建数据库连接池、不执行迁移或调用外部服务。独立样例复制为 `.yml` 后可在此入口验证。
- 任务等待队列从无界改为可配置有界队列，默认 64；饱和时明确失败，并更新未执行目标。该初始值未经过内网负载校准。
- Agent 以前只记录预算快照，循环仍读常量；现已接通快照。新配置保存 `limits`、`toolLimits`、`invocationPolicy`；旧输入仍为 v2，旧配置按历史默认解释，未来未知版本或无效配置节点明确失败。
- 工具 schema、解析器、分页／材料限制与返回检查取同一份任务工具配置。版本指纹绑定行为参数；模型列表可将不匹配的 Agent 验证显示为 EXPIRED。缓存参数不参与工具验证指纹。
- 网络调用额度在数据库中直接冻结为 Agent 网络预算；缺少冻结额度时不回退为更大的公共上限。剩余一次尝试时关闭重试并允许这次调用；输出错误保留实际尝试次数，终止轮计数不会漏记。
- 容量安全余量在公共调用和 Agent 侧一致；输出预留受模型最大输出限制。派生的 `maxEstimatedTokenUnits` 只作资源规模诊断，本期没有新增累计 token 或货币限额。
- 前端在运行配置加载成功后才导入业务应用和初始化请求。失败、非法字段和不兼容版本停留在可重试页面；页面刷新重新读取配置。公开端点只有七个白名单字段并禁止缓存。
