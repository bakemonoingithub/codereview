# 已删除数据的离线物理清理

## 1. 适用范围与验证状态

交付包脚本为 `scripts/purge-deleted-records.sh`，源码位于 `deploy/scripts/purge-deleted-records.sh`。脚本只使用现有部署环境的 Bash、标准系统命令和 Docker，通过 `docker exec` 调用 `codereview-mysql` 容器内已有的 MySQL 客户端。宿主机和应用镜像均无需安装额外运行环境或数据库客户端，不开放数据库端口，不拉取工具镜像。

连接信息直接复用部署包 `.env` 的 `AGENT_DB_NAME` 与 `MYSQL_ROOT_PASSWORD`，沿用现有备份脚本的环境传递方式。密码不放在命令行参数或日志中，不新增客户端配置文件。应用配置仍遵循其既有文件加载规则，此处 `.env` 仅为部署维护工具的输入。

仅支持已应用 V10 的新路线数据库，核对 MySQL 8、身份标记、迁移历史、23 张 InnoDB 表和删除字段。未来迁移或新增表后先更新清理脚本。脚本不建库、不执行迁移、不删除旧库、不处理 Git 镜像，也不自动收缩表文件。

负责人要求本轮不另建数据库验证。当前仅完成 Bash 语法和替身自测，没有连接真实 Docker 或数据库，也没有执行真实预览、清理、并发、回滚和磁盘回收验证。脚本按现有 Bash 4.2 部署基线编写，本轮在本机 Git Bash 检查，目标内网系统的实际运行仍待验证。

## 2. 先预览

以下命令在已经部署的离线包根目录执行。帮助入口不读取配置或调用 Docker：

```sh
bash scripts/purge-deleted-records.sh --help
```

默认只读预览，检查报告、审查及旧删除资源：

```sh
bash scripts/purge-deleted-records.sh
```

只检查审查和报告：

```sh
bash scripts/purge-deleted-records.sh --kinds reports,reviews
```

只处理删除时间早于指定时刻的审查／报告：

```sh
bash scripts/purge-deleted-records.sh --before 2026-10-01T00:00:00Z
```

截止时间固定使用 UTC 格式 `YYYY-MM-DDTHH:MM:SSZ`。项目、模型、提示词及历史策略没有删除时间，带 `--before` 时这些资源全部保留并说明原因，不猜测其删除日期。

输出包含每个根记录的子表行数、主要正文字段字节、材料候选数量、保留原因和各批汇总。主要正文统计不是表文件回收量，不包含全部元数据和索引。预览会话设置为只读，不创建存储过程、临时业务表或持久辅助对象。

预览不模拟删除，因此依赖可能在实际执行前序批次后解除；共享材料也只列候选，实际执行时重新核对引用。预览期间有写入时，数量可能变化。

## 3. 执行物理删除

物理删除无法从页面恢复。执行前保存可用备份，按既有运维流程停止所有后端实例及其他数据库写入程序，数据库保持运行；先重复预览。

```sh
bash scripts/purge-deleted-records.sh --kinds reports,reviews,resources --batch-size 20 --apply --writers-stopped
```

`--writers-stopped` 是操作者对维护前提的显式声明。脚本还会拒绝运行中的 `codereview-app`，检查在途审查、报告、模型及工具调用，并取得数据库命名锁。它不能独立证明其他实例及外部写入者全部停止，命名锁也不能阻止应用写入。脚本不自动启停任何服务。

默认每批最多处理 20 个根记录，`--batch-size` 支持 1～1000。整次运行使用一个持续的 `docker exec`／MySQL 会话，每批通过同一连接完成事务、根行锁、子记录删除、数量核对和提交。子记录可能很多，批量参数不是 SQL 行数上限。

每批提交后才输出该批明细。发生错误时停止，当前未提交批次回滚，之前已提交批次保留；按已输出的批次记录排查原因后可重跑。中断清理时也发送回滚与退出请求，连接断开后未提交事务由数据库回滚。会话设置有限的锁等待及查询期限，避免无限等待。

退出码 0 表示完成遍历，仍可能有因引用而保留的记录，须核对输出；退出码 1 表示检查失败或中止。信号中断采用相应信号退出码。帮助返回 0。

## 4. 保留规则

- 只选取 `is_deleted=1` 的根记录。已删除项目下未标记删除的审查保留，不自动扩大范围。
- 审查清理涵盖结果、问题、条目、反馈、调用关联、完整调用正文、Agent 记录、执行单元、目标和配额。删除报告只清理报告、来源快照及其调用，不删除源审查。
- 保留报告必须有独立的结果、来源和证据快照。JSON 校验及材料引用核对由容器内 MySQL 完成；无法验证的来源阻塞相应审查清理。保留 Agent 的参考正文不完整，或其他任务输入结构不受支持时，保守保留原审查。
- 只检查本批任务涉及的材料。仍被调用、工具、结果、报告或任务快照提及的材料保留；不执行全库孤儿材料清扫。材料引用结构不明时不清理该任务的材料。
- 提示词、模型、项目和历史策略仍被保留记录或历史快照提及时保留。无依赖提示词连同版本清理，无依赖模型连同验证历史清理；没有明确归属的独立模型验证调用保留。
- 脚本先处理报告，再处理审查，最后处理旧资源。被跳过的根记录不阻止遍历后续记录；再次执行会重新核对剩余依赖，不承诺强行清空所有已删除数据。

完成后可再次预览。删除后的空间供数据库后续写入复用，`.ibd` 文件不保证立即缩小；表重建、文件收缩、备份及日志保留另行安排。确认结果后按运维流程恢复应用服务。
