# 审查、报告逻辑删除与离线物理清理方案

日期：2026-10-28。负责人已授权实施前后端及物理清理脚本，包含其修订后的删除原型；代码已实现，工程检查记录见第 6 节。按负责人要求不新建数据库验证，未升级现有数据库、启停服务或执行真实清理。

本方案响应负责人关于审查／报告删除及清理已逻辑删除数据的请求。页面基线为当前 `ReviewCenter.vue` 和 `ReportList.vue`；[独立原型](prototype.html)只使用模拟数据。业务规则已纳入[业务契约第 12 节](../business-contract.md#12-审查报告删除与离线清理2026-10-28)。前五节保留方案依据，已实现范围及验证限制以第 6 节和[运维说明](operations.md)为准。

## 1. 已核对现状

- 当前库迁移链为 V1–V9。`review_task` 和 `report` 没有删除标记或删除接口。项目、模型及提示词使用 `is_deleted`；历史 `review_strategy` 表也保留该列。
- 项目删除不级联删除历史审查；本次容量分析中，49 个审查仍关联已删除项目。项目已删除不等于这些审查已经逻辑删除。
- `report_source.source_snapshot` 已复制来源结果、反馈和证据正文；Agent 的参考结果正文保存在任务输入快照中。物理清理仍须验证快照完整，不能仅凭源 ID 判断可删。
- 大头为 `model_call` 的完整请求。清理只删除任务主记录不能有效释放这一部分，也会制造孤儿数据。

## 2. 页面行为

1. 审查中心和报告列表增加单条「删除」入口。首版不增加批量删除、回收站或恢复入口。
2. 审查允许删除 `SUCCEEDED`、`PARTIAL`、`FAILED`、`CANCELLED`；其他状态禁用，提示先等待结束或取消任务。
3. 报告允许删除 `INPUT_FROZEN`、`SUCCEEDED`、`FAILED`；排队和生成中禁用。待生成报告删除与发起生成通过同一行的条件更新互斥。
4. 确认弹窗只说明记录名称、删除后的可见性及业务影响。删除审查时说明已生成报告保留冻结内容。按负责人 2026-10-28 的修订要求，用户页面不展示数据库空间或清理脚本说明；这些内容仅保留在运维方案中。
5. 删除完成刷新列表、总数及分页；最后一页删除后回退有效页。失败时保留当前列表并显示原因；不在前端先移除后忽略失败。
6. 被删除审查不再出现在审查列表、统计、报告候选或 Agent 参考结果候选。直接详情、调用、材料、结果、反馈写入及复制输入入口统一返回不可访问；通用 `model-calls` 路由也须校验所属任务／报告。
7. 报告详情、来源快照、调用、下载、继续生成均校验报告未删除。来源审查删除后，现存未删除报告仍可阅读冻结来源，原审查跳转显示「原审查已删除」。物理清理后也按来源不可用处理，不使冻结阅读依赖源任务存在。

## 3. 后端及迁移

- 新增 V10 追加迁移，为 `review_task` 和 `report` 增加 `is_deleted TINYINT NOT NULL DEFAULT 0`、`deleted_at DATETIME(3) NULL`，以及适合删除集合扫描的索引。不改已执行迁移。
- `DELETE /api/v2/review-tasks/{id}?expectedRevision=…` 与 `DELETE /api/v2/reports/{id}?expectedRevision=…`，成功返回 204。首次删除必须同时匹配未删除、允许状态和 revision，写删除时间并增加 revision；状态或版本竞争返回 409。重复删除已逻辑删除记录可返回 204，物理删除后不存在返回 404。
- 专项和 Agent 共用任务删除接口。采用统一的可见性校验；审计所有服务端联表、统计及直接 Mapper 查询，避免仅依赖一个列表过滤或实体注解。
- 处理幂等键：被删除任务不复活；同项目原键再次提交返回明确冲突，提示使用新键。物理清理后该键随任务消失，历史幂等保证不跨清理期限。
- 报告选材冻结与审查删除按任务行锁串行化；冻结先完成时保留已冻结报告，删除先完成时拒绝新选材。Agent 新建参考结果也校验源任务可见，并在并发删除边界保证输入快照完整。
- 运行中的任务、报告不允许逻辑删除。删除标记与现有取消机制分开，不在删除请求中隐式取消。

## 4. 清理脚本设计

当前实现为 `deploy/scripts/purge-deleted-records.sh`，交付包中位于 `scripts/`。按负责人后续修订，复用现有 Shell、Docker、数据库容器内客户端及 `.env`，不增加宿主机或镜像运行依赖，不新增客户端配置文件。脚本只连接已存在的目标库，校验库身份及 V10 列，拒绝旧库或结构不完整的库。

默认只预览；`--apply` 才执行写入。支持 UTC 删除时间截止值、逗号分隔的类型选择及每批根记录上限；不指定时间时表示全部已标记记录。预览输出每类候选、子表行数、正文逻辑字节估算、保留及阻塞原因，不把逻辑字节当成预计可回收磁盘空间。`--apply` 逐批重新核对候选，不盲目执行过期预览。

| 清理根对象 | 必要处理 |
| --- | --- |
| 已删除报告 | 删除所属 `model_call`、`report_source`，再删除报告；不得删除来源审查 |
| 已删除审查 | 删除所属调用与 `call_material`、工具记录、Agent 进度、执行单元、文件目标、配额、结果问题／条目及反馈，最后删除任务；反馈覆盖 ISSUE、RESULT、PATTERN、COUPLING 主体 |
| 共享源码材料 | 仅检查本批待删任务涉及的材料，核对保留的调用、工具材料、结果 provenance 和报告快照引用；仍被保留记录使用的材料保留。引用无法解析时保留并报告。不扫描并删除全库所有无调用关联材料 |
| 已删除项目 | 仅在没有保留的审查和其他依赖时删除；不能因为项目标记删除就自动扩大到未标记审查。存在引用则跳过并列出阻塞数量 |
| 已删除提示词 | 核对保留策略及任务／报告的读取依赖；冻结快照可独立读取且不存在实时依赖时删除版本，再删除提示词，否则跳过 |
| 已删除模型 | 删除所属验证历史；核对验证调用归属及所有保留任务／报告／策略的实时依赖，无法证明独立的记录保留，不凭空推断调用归属 |
| 历史已删除策略 | 无保留依赖才删除；不清除未删除策略，不恢复策略管理页面 |

补充约束：

- 「清理所有」表示遍历所有已标记对象并删除满足依赖规则的部分，不承诺强行删除所有候选。输出每类已删、保留和失败数量。
- 现有项目、模型、提示词没有 `deleted_at`。当指定时间截止时，这些旧资源不猜测删除时间，跳过并说明；需要时可显式选择清理全部旧删除资源。
- 写入模式安排在停止所有后端写入实例及相关写入工具的维护窗口；脚本验证无在途任务／报告并加数据库命名锁，防同类清理并发。命名锁本身不能阻止应用写入，不能以零在途记录声称已证明服务停止。文档明确该前提，本轮不启停服务。
- 每批在 InnoDB 事务中重新核对删除标记、状态、依赖和锁定根行；有异常整批回滚，已完成批次报告保留，重复执行不重复删除存活数据。先报告、再任务、再无引用资源。
- 保留报告引用源结果 ID 不视为悬空错误：冻结快照独立且完整时可删除源审查；无法验证快照正文及证据完整时阻塞该源任务的物理清理。
- 不处理旧库、Git 镜像、日志、备份或未归属本批对象的模型验证调用。不自动执行表重建、`OPTIMIZE TABLE` 或其他收缩操作。
- 物理 DELETE 后表内空间可供后续写入复用，但 `.ibd` 文件不保证立即缩小；磁盘收缩另行评估和授权。

## 6. 实施与工程检查

### 6.1 已实现范围

- V10 追加迁移为审查和报告增加删除标记、UTC 删除时间与清理索引；实体使用根记录逻辑删除过滤。
- 两个 DELETE 接口返回 204，携带 `expectedRevision`。根行锁及条件更新保护状态和版本，重复删除已标记根记录返回 204。专项和 Agent 共用审查接口。
- 审查／报告列表携带当前 revision；删除入口、业务影响弹窗、运行记录禁用、失败保留与空末页回退已实现。删除弹窗没有数据库空间或清理脚本文案。
- 通用模型调用读取校验根归属，反馈校验所属审查且写入事务锁定根行，报告候选先过滤已删除任务再分页。报告选材冻结锁定来源任务；Agent 新建参考在创建事务中再次锁定并校验来源。
- 历史幂等键遇到已删除任务明确拒绝，唯一键竞争后也检查删除历史。物理清理后原幂等键不再保证历史重放。
- 报告来源接口增加 `originalTaskAvailable`，当前状态不写回冻结快照；源审查删除后，冻结阅读继续，原审查跳转隐藏并说明不可用。
- 清理脚本使用持续 MySQL 客户端连接，默认只预览；写模式要求维护声明、空闲检查及命名锁，按批锁定根行并在一个事务内删除子记录与根。失败停止并回滚当前批，先前提交批保留。根记录按 ID 前进，可跳过阻塞对象而不死循环。
- 脚本覆盖已删除报告、审查、项目、模型、提示词及历史策略。仍被保留记录或快照提及的旧资源保守保留；未明确归属的模型验证调用不推断删除。共享材料只处理本批候选，引用不明则保留。

## 7. Shell 清理替换（2026-10-28）

负责人指出不得默认新增运行依赖，要求删除原实现并采用现有部署环境完成清理。已移除 Python 清理脚本、客户端配置样例和对应 Python 单元测试；当前唯一交付入口为 `deploy/scripts/purge-deleted-records.sh`。不调整应用镜像，不安装宿主机客户端，不开放数据库端口，不下载维护工具镜像。

脚本复用 `common.sh` 的部署目录定位、`.env` 读取及数据库容器健康检查，使用一个持续的 `docker exec -i` 会话调用容器内 MySQL。密码通过现有环境传递方式注入，SQL 返回只包含 ID／计数。默认预览会话只读；执行要求维护声明、已停止应用容器、无在途记录及命名锁，每批事务校验实际删除行数。报告快照及共享材料校验在数据库内完成，无宿主机 JSON 解析器依赖。

清理范围和保留规则见[运维说明](operations.md)。检查：主脚本及 `_purge_selftest.sh` 的 Bash 语法通过；15 项无数据库替身自测通过，覆盖参数拒绝、删除顺序、来源快照阻塞、资源引用保留、截止时间、持续会话、预览不写、事务提交、SQL 失败不提交、运行中应用／在途任务／缺少 V10／命名锁占用拒绝。Docker 和 MySQL 都由 Bash 替身模拟。

发布流水线已加入同一套无数据库 Shell 检查，尚未触发远端运行。离线包检查覆盖 YAML 解析、组装 Bash 语法、模拟复制及旧附件缺失检查；旧配置文件和 Python 测试不再进入交付包。前后端没有因本次脚本替换而修改，本次不重复前序应用测试。本轮仍不连接真实 Docker／数据库、不另建库、不启停服务或执行真实删除；没有把模拟回滚当作真实事务验证。
