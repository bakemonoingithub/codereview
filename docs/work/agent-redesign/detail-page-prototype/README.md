# 详情页原型与 Vue 落地核对

本目录的 [交互原型](index.html) 用示例数据讨论专项审查、Agent 分析和报告详情的信息组织。它不是正式页面，不连接服务，不保存反馈，也不会执行刷新、取消、复制或下载。原型中的名称、代码、时间、数量和结论均为示例。

## 本轮可确认的范围

- 顶部切换三类详情页，右侧切换执行状态。
- 每个详情页展示结果、输入与配置、执行记录三个入口；专项可切换目标文件，报告和 Agent 可查看示例来源或代码证据。
- 状态覆盖正常完成、执行中和失败等场景；专项补充部分完成和取消，Agent 补充材料不足和取消，报告补充已冻结但尚未生成。
- 原型只表达信息层级及交互方向，不将示例内容视为真实结果，也不将原型批准视为功能验收。

## 对照现有页面

| 信息 | 当前依据 | 落地前需核对 |
| --- | --- | --- |
| 专项的任务状态、目标、逐文件结果及反馈 | `TaskDetail.vue`、`SpecialistResultView.vue`、任务详情及统计接口 | 保留问题级与结果级反馈的差异、评论及草稿保护；部分完成时保留真实文件状态 |
| 专项输入与配置 | `TaskView.config`、目标的 `note` 和任务版本字段；当前「审查输入」展示关联材料 | 区分任务快照、目标文件要求、关联材料和实际调用；确认历史数据缺字段时的显示方式 |
| Agent 结果及证据 | `AgentTaskDetail.vue`、`AgentResultPanel.vue` 和结果接口 | 保留材料不足、未解决事项及证据的版本／行号；执行终止但无结果时不能伪造结果 |
| Agent 多提交比较 | P33.3 记录显示输入快照保存逐项比较关系；当前页面使用的 `copy-input` 类型只声明提交列表 | 检查正式读取接口是否返回每项基线及根提交信息；不能只凭原型推断当前接口已提供 |
| Agent 执行记录 | 当前详情页读取工具调用，公共任务 API 另有模型调用接口 | 明确权限、分页、实际数据关联及模型调用在 Agent 路线下的可用性；不可把工具记录称为全部模型调用 |
| 报告正文、来源及生成配置 | `ReportDetail.vue`、报告详情和来源快照接口 | 保留冻结来源、引用、规则正文、下载及失败／已冻结状态；多项目名称和缺失数据要按实际接口处理 |

## 原型到 Vue 的验证方式

1. 先确认三个页面的信息层级和不同状态；需要调整时先改原型。
2. 将确认的区域逐项对应到现有 Vue 组件、状态和接口，标明复用、调整和缺失项；任何缺失的字段或行为单独讨论，不用虚构数据填补。
3. 实施时优先使用项目现有控件和设计变量。把原型中的间距、字号、宽度、颜色和响应式断点作为对照目标，同时检查真实控件的弹窗、加载、空态、错误态及长文本。
4. 在同一浏览器、视口和相近数据下逐项对照正式页面与原型，验证页面层级、布局、文字换行和交互。对控件、数据长度或既有能力造成的差异逐项记录并调整。
5. 分开记录工程检查、真实数据验证和负责人视觉确认。原型、自动测试或构建成功都不能单独证明正式页面与原型完全一致。

原型中的按钮用于展示位置；「清空、取消、下载、反馈保存、调用阅读」等行为必须在正式页面中分别验证。涉及详情页整体结构或 Agent 调用记录布局的框架实现，按工作区约定在原型确认后进行。
