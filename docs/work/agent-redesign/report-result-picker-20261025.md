# 报告审查结果选择弹窗

日期：2026-10-25（Asia/Taipei）。工作树：`H:\myProjects\aiCodeReview\code`，分支：`dev`。

## 1. 依据与范围

负责人要求报告生成表单选择审查时使用类似提交选择器的弹窗，后续明确「视觉测试我来做」。行为以[契约第 6.4.3 节](business-contract.md#643-报告审查结果选择弹窗2026-10-25)为准。

先制作[HTML 原型](report-result-picker.html)，再按已有提交选择器的独立弹窗、草稿勾选、确认回填及取消保留交互接入现有框架。视觉验收由负责人执行，不以工程检查代替确认。

## 2. 实现

- `ReportCreate` 主表单保留报告信息、已选材料摘要和生成操作，点击按钮后再读取候选，避免初次打开表单就加载完整候选区。
- 新增 `ReportResultPickerModal`，支持项目／类型筛选、已加载内容关键词筛选、触底或按钮继续分页、虚拟列表和已选摘要。以 `resultId` 多选去重，遵守现有冻结接口一次最多 200 份结果的限制。
- 选择草稿独立于表单；跨页、跨筛选保留，允许清空后确认。取消或关闭后重新打开，从主表单已有材料回填。
- 翻页成功后才更新游标；失败保留最近成功列表与游标，重试原页。刷新失败保留原列表，关闭／切换筛选／卸载后忽略迟到响应。
- 预览使用现有专项结果及 Agent 结果接口；Agent 正文与证据在弹窗内阅读，不跳离报告表单。切换或关闭预览时拒绝迟到正文；材料不足及未解决事项继续展示。
- 后端候选、冻结与生成接口保持原实现，本轮未操作数据库、启停服务或生成新报告。
