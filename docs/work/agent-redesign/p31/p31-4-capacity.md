# P31.4 整文件容量、授权拆分与程序去重

状态：完成（2026-10-21，Asia/Taipei）。范围为本地容量规划、固定样本单测与结果归并；没有真实大文件仓库或模型容量样本。

## 1. 交付

| 能力 | 位置 | 说明 |
| --- | --- | --- |
| 容量规划 | `SpecialistSplitPlanner` | 完整目标优先；未开启智能拆分时超限直接 `CONTEXT_LIMIT` |
| 授权拆分 | 同一规划器 | 先按从低到高优先级裁剪辅助材料；仍超限才按类型/成员连续行区间拆分 |
| 片段覆盖 | `SpecialistUnitPlan` | 每个片段保留 SHA、路径、侧和原始行号；文件头、类型头、字段、方法、初始化块与类型尾部均进入覆盖 |
| 有限兜底 | 同一规划器 | 单块超限按行二分；单行仍超限返回 `UNSPLITTABLE`，每文件最多 32 个单元 |
| 程序去重 | `SpecialistResultMerger` | 问题按位置+类别+标题+原因；模式按名称+角色+依据位置；耦合按标题+解释+dependencyIds |
| 辅助保留 | 同一规划器 | 拆分单元仍尽量携带能容纳的辅助声明；放不下时保留已裁剪单元 |

## 2. 边界

- 拆分只产生带原始行号的片段材料，不截断单行，不改变目标 SHA/路径/侧。
- 默认整文件；只有任务快照的 `smartSplit=true` 才允许裁剪与拆分。上下文超限不能由内部字符阈值自行触发拆分。
- 去重只合并可确认的重复项，不追加 LLM 综合复查，也不把片段结果写成完整模块结论。
- 当前片段的摘要仍以成员/行区间为主；跨片段业务关系不重建，符合 P29 “轻量兜底”边界。

## 3. 验证

- `SpecialistSplitPlannerTest`：5 项，覆盖整文件保留辅助材料、关闭拆分、成员边界拆分与原始行覆盖、辅助材料优先裁剪、单行不可拆。
- `SpecialistResultMergerTest`：3 项，覆盖问题同位置不同原因不合并、模式去重、耦合 dependencyIds 去重。
- 规划器用真实组装与容量估算，模型窗口和输出预算为测试固定值；不是目标仓库实测。
