问题 01高严重度可靠性

事务提交后 dispatch 失败会使任务永久停留 QUEUED

问题说明

任务与目标、额度在事务内落库并置为 QUEUED（第 117、592 行），事务提交后第 143 行直接调用 dispatcher.dispatch(task.getId())。该调用位于 try/catch 之外，若其抛出异常（如线程池拒绝、执行器不可用），create 会向调用方返回失败，但任务已持久化为 QUEUED 且没有任何补偿或状态收敛；调用方重试若未带同一 Idempotency-Key 会创建重复任务，若带同一 key 则 replay 返回一个从未被调度的 QUEUED 任务。

修改建议

将 dispatch 调用纳入异常处理：捕获后通过 dispatcher.terminate/finish 将任务与目标收敛为明确失败态（如 EXECUTOR_UNAVAILABLE）再抛出，或改为事务提交后可靠投递（如 outbox/重试队列），确保 QUEUED 任务最终一定被调度或标记失败。
