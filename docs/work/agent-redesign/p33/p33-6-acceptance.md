## 2. 混合报告联调

真实项目 `codereview`（`01M2FZ8HA8H6CVXRTKA15JV7GQ`，固定版本 `b8b0b50e…`），模型 `DeepSeek(默认)`，来源为 1 个 Agent 结果与 1 个专项 `ISSUE` 结果。

### 2.1 失败样本

1. 第一次冻结返回 500：Agent 结果 `provenance.materials` 使用 `materialId` 作为键，而冻结逻辑只认 `id`。已改为新结果写 `id`，并对历史结果兼容 `materialId`。
2. 第二次冻结成功但 Agent 快照正文被当作纯文本保存，导致报告表格出现「答案状态 UNKNOWN、引用 0、未解决 0」。已改为结构化解析 Agent 正文，保留 P32 纯文本兼容。
3. 两次失败报告均保留在库中，未删除或改写成通过。

### 2.2 成功样本

报告 `01M5HF6VYW952ZD5888TVZXYK8`：

- 冻结来源 2 个：`AGENT` 与 `ISSUE`；Agent 来源快照 `answerStatus=ANSWERED`、17 处引用、3 项未解决、`headSha=b8b0b50e…`、23 条材料。
- 生成 `SUCCEEDED`，正文 8664 字符；同时引用 `[S1]` 与 `[S2]`，包含「Agent 答案状态：ANSWERED；引用 17 处；未解决 3 项」和 Agent 结论的具体位置。
- 下载接口返回 200，Markdown 14614 字节；来源抽屉所需的冻结快照与材料均可读取。
- 报告同时保留两类来源的限制：Agent 的 3 项未取得与专项的单文件覆盖限制。
