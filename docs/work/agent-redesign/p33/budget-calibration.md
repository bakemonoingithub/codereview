# P33.1 实际项目预算与接口对照实验

日期：2026-10-22（Asia/Taipei）。状态：负责人按 D-90 授权的设计实验；材料不足结果允许选材已确认，模型只使用 DeepSeek。本轮不启动 P33.2、不修改正式业务代码或数据库配置。

## 1. 实验对象与方法

使用数据库项目 `codereview`，ID `01M2FZ8HA8H6CVXRTKA15JV7GQ`，项目修订 4，仓库 `https://github.com/bakemonoingithub/codereview`，与本地 origin 一致。远端 `refactor/agent` 的固定提交为 `b8b0b50e4cce07188debd775ee80f70e13709cf5`；本地 HEAD 当时为 `af82b34`，因此本地所有对照都显式指定远端固定 SHA，不读取移动工作副本，不推送代码。

模型读取数据库中的 `deepseek-flash`，配置 ID `01M23AKQZRG40082QFECKMC36N`、修订 2、声明窗口 1048576、最大输出 393216。使用已验证的非思考配置 `reasoning_effort=none`、原生 tools、tool_choice=auto；没有调用 Qwen。

接口侧经运行中的 `/api/v2/projects/{id}` 取得固定路径清单、文件、行范围、提交详情及 diff。本地独立使用 `git ls-tree`、`git show`、`git grep -F`、`git diff`，两边固定同一 SHA 或同一第一父提交比较关系。

正式 Agent 代码搜索端点尚不存在。本轮临时 HTTP 工具桥从正式读取接口取得源码，在 API 返回的固定版本文本中执行字面量搜索；搜索结果再与独立本地 git grep 对照。工具桥的搜索实现不读取本地源码作为接口结果，也不作为正式镜像检索的交付或性能证明。其内容缓存位于已忽略的 `backend/target/p33-budget-experiment`，模型凭据仅从只读 Java 子进程管道进入内存，不入证据文件。

实验输出使用用于计量和取证的最小 schema，例如未要求正式结果的 summary 字段。完成及引用检查是本轮实验检查，不代替正式 schema 全字段、工具参数上限或任务发布事务的验收。

## 2. API 与本地结果对照

- 固定版本 640 个文件路径与 git ls-tree 完全一致；树不截断。
- API 文件缓存以「SHA + 路径」为单位复核，共 269 个文件版本与 git show 全文一致；426 个历史工具材料的声明范围也逐项核对。历史 diff 材料的额外末行问题另列于第 4 节，不把历史 envelope 全部标为严格匹配，详见 [audit-and-replay.json](evidence/budget/audit-and-replay.json)。文件版本数量不是不同文件路径的数量，缓存包含多个固定版本。
- 搜索覆盖正命中及零命中：`getCancelRequestedAt`、`requireActive`、`source_snapshot` 和固定不存在的标记。实际模型追加的查询同样对照路径、行号与命中内容；截断结果不宣称全量。
- C1 为 `2660ce0bb90bee33fc0573e672a58d38a339d4c7 → b8b0b50e4cce07188debd775ee80f70e13709cf5`，是合并提交相对第一父提交，30 个变更文件。
- C2 为 `dfe2d5d7668182136eed47c9d4cb3e81b561f1e6 → 0343a9566d2c2e3112c0ac5102887f625e875f9d`，24 个变更文件。两次非连续比较不合成为首尾净差异。
- 变更清单与 git diff --name-only 对照；patch 不要求字符串完全相同。GitHub 与本地 Git 的 `@@` 后函数说明、hunk 分组可能不同，故同时核对原始双方全文，并把 API patch 应用到 before 后与本地 after 对照，保留原始范围、增删及上下文校验，不能只删除差异后声称相等。

完整差异对照见 [all-diff-comparison.json](evidence/budget/all-diff-comparison.json)，之前的对照和失败样本保留在 evidence/budget。缓存及本机 Git 的计时不代替远端冷镜像同步或内网承载实测。

最终全量对照覆盖 54 个不同的「比较关系 + 路径」组合，共 58 次 patch 校验（含预检重复项），全部应用后与对应本地 after 一致；5 个组合的 hunk 文本分组或说明不同，但语义对照通过。修正工具材料切片后，另完成 333 次返回材料区间核对。本机固定 SHA 的四类字面量 grep 各测 10 次，中位数约 78 ms；仅作本机读取参考。

## 4. 必须保留的失败与取舍

### 4.1 搜索片段不能冒充更大范围

初次取消链路结果有三处引用超出所选材料：例如搜索仅返回第 71 行，却引用 71–73 行；另一处跨越两个读取片段边界。首份提交被拒，返回具体材料及合法范围后，一次纠错通过。原证据见 [cancel-initial-invalid.json](evidence/budget/cancel-initial-invalid.json)，修正后见 [cancel.json](evidence/budget/cancel.json)。

保留严格引用范围校验和最多 2 次有限纠错；搜索返回上下文与实际行范围，模型需要更大范围时应重新读取或使用已经读到的完整材料 ID。不能由程序暗中扩大引用范围。

### 4.2 无后续入口的截断会制造循环

初版实验 read_diff 只截取 patch，没有分页或可引用的原始材料 ID。模型反复请求两份同样的前端测试 diff，最终 32 轮、70 次工具调用仍未完成，见 [commits-without-pagination.json](evidence/budget/commits-without-pagination.json)。该结果不计为通过。

工具桥补齐 hunk 分页、nextCursor、前后侧可引用原始材料、重复查询提示后，同一问题完成，见 [commits-without-program-facts.json](evidence/budget/commits-without-program-facts.json)。这些改动同时发生，不能把改善单独归因于其中一个参数，也不能归因于放宽次数；该样本实际只使用 12 轮、30 次工具。

正式工具必须有可继续的分页或精确原始范围出口；对完全相同请求复用缓存并提示已读。增加连续无进展的简单保护，不引入规划器、反思 Agent 或额外总结调用。

### 4.3 引用合法不代表结论正确

上述 12 轮结果虽然引用检查全部通过，却声称 C1 和 C2 没有共同文件。API 完整清单及本地命令都确认交集有三项：

- `frontend/src/components/ReportSourceDrawer.vue`
- `frontend/src/views/ReportCreate.vue`
- `frontend/src/views/__tests__/ReportCreate.spec.ts`

这份结果的语义质量只记部分通过。后续把文件集合交集作为程序确定事实经统一组装提供，再用同一问题复测，保留最终 [commits.json](evidence/budget/commits.json)。这不新增语义自动核验器：程序计算可确定的集合事实，模型解释业务影响，真实效果仍需人工验收。不能宣传「原生工具能调用、引用有效」就等于 Agent 结论已验收。

实验早期还修正了工具桥自身的版本路径清单隔离、Git 非 ASCII 路径引用及 diff 辅助说明比较方式。这些是实验适配错误，不作为正式后端缺陷或通过证据。

末轮独立审计还发现实验 diff 材料切片在声明末行后多附了一行真实上下文。历史模型输入及统计保持原样，审计逐项标明此问题；引用校验一直只允许声明范围内的位置，没有放行额外末行。现已修正切片，并通过不调用模型的全量 diff／原始材料范围对照复验。不能把历史 envelope 的完整性写成毫无缺陷，预算仍按当时实际发送量统计。

其中 308 个历史 envelope 含这一额外上下文行，所有声明范围内的内容与 Git 原始位置一致；这与「内容来自错误版本」不同，但仍是必须修复的完整性标注问题。预算及质量统计不改写历史输入，不通过修订原始证据伪装为此前就已正确。

## 5. 首版默认预算及理由

负责人明确内网基本无需考虑花费。本设计不设货币上限；数值用于防止耗时失控、上下文超限和无效循环，统一冻结到任务快照。

<!-- BUDGET_START -->
| 项目 | 默认值 | 实验依据与余量 |
| --- | --- | --- |
| 模型轮次 | 48 | 最复杂的最终样本为 30 轮；32 轮接近边界，48 留出复杂任务及有限纠错余量 |
| 全部网络尝试 | 96 | 与每轮最多一次传输重试对应，仍低于公共 200 上限；每次真实尝试单独记账 |
| 工具尝试 | 192，单轮最多 4 个 | 最复杂样本 59 次；与 48 轮上限相容，错误参数也计数 |
| 总期限／单次模型超时 | 20 分钟／120 秒 | 样本级保留较大内网波动余量；最长单次模型响应约 24 秒；等待和准备均计入总期限 |

| 连续无进展 | 完全相同工具、参数、返回且无新材料持续 3 轮 | 第二轮先提示；正常翻页和有效纠错不计入；正式实现仍需验证 |
| 工具返回 | 总 envelope 32 KiB，单材料正文 24 KiB，读取默认 200／最大 400 行 | 大材料分页；精确保留原始范围，不通过删除历史延长任务 |

保守累计字节估算不能直接当作实际已消耗 token。本轮分别回放「返回 usage 后正常结算」与「usage 全部缺失、保留预留」；原 100 万门槛在部分保守情形会过早终止。现改为按最大合法请求和网络尝试上限推导的总资源保险，避免把无花费约束的内网任务卡在任意小额门槛。

上下文阈值仍按完整序列化请求的保守计量执行，不直接采用本轮 token／字节比例扩窗。日志中的 usage 比例只能作为观察，不能保证未来中文、代码、schema 或提供方模式都相同。没有发出接近完整窗口的超大请求，不把 80% 算术回放写成窗口能力已实测。

## 6. 验证范围与后续落点

- 正式代码搜索 API、共享镜像上的冷／热检索、权限与缓存隔离、预算原子计量、取消竞争、正式任务发布及真正的无进展保护仍须 P33.2–P33.6 实现和验证。
- 搜索桥是设计实验，直接扫描 API 文本；工具计时包含对照检查，不能当作正式服务的性能数字。
- GitHub 两次变更和当前机器可验证，不代表最大 2894 文件内网仓库、Gitea、并发及完整 1M 窗口已覆盖。
- 实验中恢复保存的被拒提交只用于有限纠错对照；不是产品任务恢复功能，不改变首版不恢复原会话的契约。
- 预算边界和无进展回放是离线计算，不替代正式执行器对第 N 次／第 N+1 次、额度预留及迟到发布的工程测试。
- 未执行生产数据库迁移、配置修改、封存、部署或服务重启，未调用 Qwen。
