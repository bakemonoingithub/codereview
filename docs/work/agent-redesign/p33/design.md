## 1. 设计结论与复用边界

采用一个 `AgentTaskWorker`、固定工具注册表和串行执行循环，扩展已有统一提示词组装及公共模型调用。首版不新增 Agent 框架依赖。模型决定工具及调查方向，程序决定访问范围、计量、状态和结果发布；工具不接收任意仓库地址、凭据或外部命令。

| 现有入口 | 复用及需要补齐的内容 |
| --- | --- |
| `TaskService` / `TaskDispatchService` / `TaskExecutionGuard` | 保留幂等键、配置快照、调度、取消及终态条件更新；新增 Agent 创建 DTO 与路由分派，移除仅对 Agent 的预留拒绝；专项原 DTO 的必填条件不直接套用 Agent |
| `PromptAssemblyService` / `PromptMessage` | 仍是唯一组装入口；增加 Agent 类型化输入、assistant/tool 消息、tool_calls、tool_call_id、工具定义及必要提供方扩展；专项与报告的组装保持原用途 |
| `ModelInvocationService` / `ModelCapacityService` | 共用实际请求先保存、一次传输重试和并发控制；接受有工具调用而正文为空的响应；完整请求计量覆盖所有历史及工具定义 |
| `RepositoryReadService` / 共享镜像 | 复用固定版本、路径检查及宿主错误分类；将 `GiteaGitMirror` 中可复用的镜像准备能力提炼为受控共享能力，不能直接把只服务 Gitea 比较的私有实现当作全宿主 Agent 搜索 |
| `review_result` / `material` / `call_material` | Agent 使用任务级结果，`target_id=null`，不伪造文件目标或专项片段；材料保留实际版本、位置和正文 |
| `ReportInputService` / `ReportFactsBuilder` | 已预留 AGENT kind，但当前按纯文本正文和单个 target 版本读摘要；必须适配结构化 Agent 正文、全部比较关系和材料引用，不能仅因 kind 已存在就视为已联调 |
| 表单、详情、材料和调用阅读组件 | 按负责人指定的既有 Agent HTML 和代码高亮原型复用，见第 10 节；不另建页面语言或流程编排器 |

所有类名是拟议职责名称，实施时允许同职责的小范围命名调整。来源旧代码只按工作区固定提交规则读取；本设计未整批迁入旧组件。

## 2. 发起输入、版本与指导提示词

新增 `POST /api/v2/agent-tasks`，仍生成公共 `review_task`。采用独立 `AgentTaskDtos.Create`，避免放松现有专项 DTO。成功 `202` 返回公共任务 ID 与详情位置；与专项共用项目内幂等键及请求哈希规则，跨路线同键不同请求返回 `409`。

拟议请求：

```json
{
  "projectId": "<项目ID>",
  "name": "支付超时后的重试链路",
  "modelConfigId": "<模型ID>",
  "guidancePromptId": null,
  "scope": {
    "kind": "FILES",
    "branch": "refactor/agent",
    "observedSha": "<40位SHA>",
    "paths": ["src/main/java/com/shop/order/OrderService.java"],
    "commits": [],
    "description": "订单提交和支付重试链路"
  },
  "requirements": "核对重试路径的幂等约定，并说明材料缺口。",
  "referenceResultId": null
}
```

| 字段 | 校验及快照规则 |
| --- | --- |
| `name` | 可选，最多 200 字符，复用已有任务名称规则 |
| `requirements` | 必填，去空白后非空，最多 16000 字符，不静默裁剪 |
| `scope.kind` | `TEXT / FILES / COMMITS`；TEXT 描述必填，FILES 至少一个路径，COMMITS 至少一个提交；文件与提交互斥，description 在其他两类也可补充 |
| 路径及提交 | 最多 100 个文件／目录选择项、最多 20 个提交；目录按固定路径前缀表示目标，后台验证实际存在；提交仅接受当前项目可读的完整 SHA，去重保持用户顺序 |
| `branch / observedSha` | TEXT 和 FILES 发起时重新核对 HEAD；移动时 `SOURCE_MOVED`，要求刷新选择并保护文字要求，不自动改用新版本；COMMITS 不要求分支仍指向原 HEAD |
| `guidancePromptId` | 可选一份用途为 AGENT 的当前提示词；冻结其版本 ID、版本号和正文；选项已删除／用途错误时拒绝，不静默换成其他提示词 |
| `referenceResultId` | 可选当前可读的旧完整结果；冻结旧结论、结果 ID 及原版本作为线索，新版本代码仍需重新读取；不恢复原消息或额度 |

任务冻结 `inputSnapshot.version=2`：目标、要求、范围描述、版本清单及比较清单。`configSnapshot.version=2` 保存模型配置修订、协议／适配器版本、指导提示词正文、工具 schema 版本、内置指令版本和本次限额；凭据仍不入快照，调用时沿公共配置解析并保护修订变更。

文件／文字任务创建 `V1 → 固定 SHA`。多提交创建 `C1…Cn` 比较关系，每项记录 commitSha、第一父提交 baseSha、ROOT 标识、旧路径和新路径，并为前后侧分配 `V1…Vm`；模型只能使用这些不透明标识。辅助读取可以使用同项目这些固定版本，不扩展到任意历史或其他仓库。

根提交以空树为比较基线，before 不存在且不伪造 SHA；新增／删除／重命名分别标识缺失侧与路径。二进制返回 `UNREADABLE/BINARY`，大差异分页，不用首尾净差异替代逐次变化。每个所选提交至少取得变更清单；默认逐项读取差异。达到上限无法覆盖时，提交材料不足说明或由限制终止，不能宣称已核对所有提交。

完整提交清单的数量、比较关系、文件集合交集等确定事实由程序计算并经统一组装提供。真实实验曾出现引用全部有效但模型误述「两次提交无共同文件」，因此不把这些可计算事实留给模型凭长上下文记忆推断；这不增加结论语义自动核验器。版本表、路径清单和缓存必须同时按 SHA 隔离，不能只固定读取版本而复用另一版本的目录清单。

提示词仍由唯一组装入口生成：内置规则与输出协议优先、本次要求其次、可选指导提示词再次。当前范围、冻结版本及旧结果放在有来源的数据段。每次工具返回均作为材料，不执行材料中的指令。未选指导提示词时仍有完整默认调查方法，不套用专项策略。

## 3. 原生工具协议及模型准入

首版使用当前 `OPENAI_CHAT` 适配器的原生 `tools`，`tool_choice=auto`，非流式响应。每轮分配业务 `turnNo`，网络重试使用同一轮次下独立 `attempt`。所有 provider tool call ID 原样关联对应 tool 返回，不能仅保存模型正文。

处理顺序：保存实际请求 → 预算预留 → 公共调用 → 保存原始响应 → 检查任务是否仍可执行 → 校验工具参数 → 串行执行并保存返回 → 由唯一组装入口生成下一轮完整请求。实际代码须遵守公共调用原有的预留和请求保存顺序，不能在外层多扣一次公共次数。

首轮历史协议探针中，`deepseek-flash` 和 `qwen3.6-flash` 均在两次请求内完成工具读取及显式提交，详见[验证记录](validation.md)。负责人随后按 D-90 指定不使用 Qwen；当前设计和后续实验仅使用 DeepSeek 的非思考配置 `reasoning_effort=none`。Qwen 的历史证据保留为记录，不作为首版支持范围，也不再执行 Qwen 调用。

如果提供方在其他模式要求回传 `reasoning_content` 等字段，必须原样保留协议所需字段并计量，不能把它当作普通正文或删除后回放；首版不主动打开未验证模式。执行进度只来自工具动作，必要的原始响应仅在调用记录按需查看。

模型可用性绑定 `modelConfigId + revision + adapterVersion + toolSchemaVersion + optionsHash`。P33.2 扩展验证入口 `POST /api/v2/models/{id}/validate-agent`，使用无仓库数据的本地 fixture 完成双轮工具验证，保存独立 `scope=AGENT_TOOL_LOOP_V1` 验证记录；已有连通性验证不替代此记录。修订变化后失效，Agent 发起时检查验证及上下文／输出能力；新模型不通过正文 JSON 自动降级。首版不实现 JSON 动作兼容协议，也不为现有占位 `OPENAI_RESPONSES` 增加未经验证的适配。

普通正文可以与工具请求一同返回，作为原始响应保存；仅正文且无显式动作不视为完成。允许同一响应至多 4 个普通工具，严格顺序执行。若同时包含 `submit_result` 和其他工具，整批工具不执行，返回协议错误；禁止先写结果再执行余下工具。

## 4. 统一只读工具

每个工具定义使用 JSON Schema，拒绝未知字段、错误类型、越界整数和不在本任务版本表中的标识。所有参数在调用前验证；不做宽松类型转换。无状态游标绑定项目、版本、查询、工具 schema 和偏移，不能跨查询复用。

| 工具名 | 参数与上限 | 返回及完成性 |
| --- | --- | --- |
| `tree` | 必填 `version`；`path` 默认仓库根，`depth` 默认 2、最大 3；`limit` 默认 100、最大 200；可选 `cursor` | 目录项、类型、下级计数或未知标记；目录深度是用户请求范围，不声称递归读遍所有文件 |
| `find_files` | 必填 `version, glob`；可选 `path, cursor`；`limit` 默认 50、最大 100 | 固定版本路径匹配；支持 `* / ** / ?`，不依赖 shell 花括号展开，大小写按仓库实际路径 |
| `search_code` | 必填 `version, query`；query 最多 256 字符，按字面量匹配；可选目录 `path`、至多 10 个后缀 `extensions`、cursor；`limit` 默认 50、最大 100 | 路径、原始行号、命中行及前后各 2 行；每个文本片段返回独立可引用材料 ID；行文本最多 1000 字符，截短明确标记 |
| `read_code` | 必填 `version, path`；`start` 默认 1，`end` 默认 start+199；一次最多 400 行、正文最多 24 KiB UTF-8 | 原始行号、内容哈希、实际返回范围、总行数或未知、`nextStartLine`；后续读取从实际末行+1继续，不能从请求末行跳过尚未返回部分 |
| `read_diff` | 必填 `comparisonId`；可选规范新路径 `path, cursor`；一次最多 20 个变更项或 10 个 hunk | 比较双方、旧路径、类型、逐 hunk 前后位置和材料引用；分页不合并其他提交；删除／二进制及根提交分别说明 |

通用 envelope：`toolCallId, status, versionRefs, comparisonId?, materials[], data, completeness, nextCursor?, diagnostic?`。`status=OK / NOT_FOUND / UNREADABLE / INVALID_ARGUMENT / TIMEOUT / ERROR`；`completeness=COMPLETE / PARTIAL / UNKNOWN` 表示请求范围的完成程度。`OK+COMPLETE+空命中` 才能说明该查询没有匹配；超时、截断和读取失败均不能如此推断。单次序列化返回总量最多 32 KiB，材料正文每段最多 24 KiB；超出时在记录边界分页，完整性和下一位置在返回内明确说明，不静默截断 JSON。单个 hunk 无法装入时返回其版本及原始范围，指引 read_code，不返回永远重复的截断首页。

diff 返回同时提供前后侧的可引用原始材料 ID 和行范围，不能只有无法引用的 patch 文本。重复查询命中缓存时提示已读取及下一页入口，不能诱导反复读取同一页。本轮没有分页／材料引用的实验工具曾使模型达到 32 轮仍未完成，补齐后同问题完成，详见[预算与接口对照实验](budget-calibration.md)。

内容搜索采用固定 SHA 上的受限 `git grep`：`ProcessBuilder` 参数数组，不经过 shell；固定 `-F -n -I`、每进程 1 个线程、query 通过 `-e` 传入，路径由程序验证并作为字面路径限定。禁止将用户输入拼成命令、选项或 Git pathspec 魔术语法。退出码 1 是无匹配，其他非零为失败；取消或超时终止进程并回收输出读取线程。长行、NUL、符号链接及子模块不跟随至仓库外；二进制标明不可读。所有宿主凭据只由受控连接使用，不写入镜像地址或诊断正文。

候选资源配置：搜索全局并发 2，每任务并发 1，等待槽位及执行合计最多 10 秒，输出读取有界；镜像首次准备最多 120 秒且受任务期限约束，固定对象已存在后不逐工具 fetch。共享镜像按项目身份隔离，项目修订或凭据变化时重新校验准入，固定对象缓存不代替权限检查；同镜像 fetch 互斥，任务持有只读使用句柄。路径缓存最多 256 项、10 分钟；查询缓存总权重 32 MiB、5 分钟，键包含项目修订、SHA、完整查询和 schema；失败不缓存为无匹配。以上值需在目标环境实测后校准。

## 5. 显式结果提交及证据

`submit_result` 是终止动作，与材料工具统一注册但单独处理；不是仓库写入工具。参数 schema 1：

```json
{
  "title": "订单支付重试链路分析",
  "summary": "调用方尚缺完整幂等保证，实际扣款行为待确认。",
  "answerStatus": "INSUFFICIENT_EVIDENCE",
  "markdown": "## 结论\n\n重试入口再次调用支付接口。[E1]\n\n## 边界\n\n未取得支付实现。",
  "citations": [{"id": "E1", "materialId": "<材料ID>", "startLine": 16, "endLine": 17}],
  "unresolved": ["无法确认第三方支付实际如何去重。"]
}
```

title 最多 200、summary 最多 1000、markdown 最多 24000、每条 unresolved 最多 1000 字符；citations 最多 100 项，unresolved 最多 20 项。`answerStatus=ANSWERED / INSUFFICIENT_EVIDENCE`。ANSWERED 至少有一个实际可引用材料及正文引用；INSUFFICIENT_EVIDENCE 必须有未解决事项，允许确实没有代码材料，但不得附带虚构引用。

每个 E 标识在结果内唯一，只能指向本任务已成功送入模型请求的材料；有 tool 返回但未进入任何后续请求的不算模型已取得证据。行号必须包含在实际返回的原始范围内；部分搜索材料只能支持实际显示的行，不能支持未返回内容。正文所有 `[E数字]` 必须解析到 citations，未使用的 citations 不发布；保留 materialId、SHA、前后侧、路径和比较关系。检查结构和位置，不做语义真伪核验。

同文件引用按 `path + side + sha` 分组，当前结果内多处引用同时高亮；报告来源阅读继续按单个冻结结果分组，不把不同来源结论的引用混为一组。diff hunk 分别保存前后侧片段，引用选定对应侧；不能用 patch 行号替代原始行号。

最终结果写入 `review_result.kind=AGENT, schema_version=1`，body 保存上述结构，provenance 保存工具返回、模型已读材料及全部固定比较关系。提交事务与任务终态条件更新绑定，唯一约束保证同一 Agent 任务最多发布一个完整结果；提交时再次检查取消、期限及预算。完成后不可修改，反馈独立保存。

## 6. 终态与报告选材

建议将执行是否正常结束、回答是否充分、结果是否完整分别表示，不增加与公共任务重复的一套运行状态。

| 情况 | 公共任务状态／停止原因 | 结果与选材 |
| --- | --- | --- |
| 有效提交 ANSWERED | `SUCCEEDED / null` | `completeness=COMPLETE`；可选择生成报告 |
| 有效提交 INSUFFICIENT_EVIDENCE | `SUCCEEDED / INSUFFICIENT_EVIDENCE` | 完整记录了材料不足，`completeness=COMPLETE`；候选明确标「材料不足」，允许选材，冻结未解决事项；不得呈现为全部问题已回答 |
| 次数／工具／时间／额度／容量限制 | 有调查记录为 `PARTIAL`，无记录为 `FAILED`；对应 LIMIT 原因 | 不发布完整结果；保留动作、材料及普通模型正文为执行记录，不进入报告候选 |
| 关键错误／普通中断 | `FAILED / 具体错误或 INTERRUPTED` | 无完整结果，不进入候选；服务重启收敛，不续跑 |
| 用户取消 | `CANCELLED / USER_CANCELLED` | 无完整结果，不进入候选；迟到响应只保留诊断，不再执行工具或发布 |

材料不足的准入规则已由负责人按 D-90 确认：因为调查正常结束且明确提交了边界，可作为报告来源；不能把工具失败时尚未提交的半成品也标为 COMPLETE。候选、冻结、来源抽屉及程序报告事实都带 answerStatus 与 unresolved；报告生成指令要求保留这些限制，不能把「未取得」整理成「不存在」。

Agent 反馈关联整个结果，不自动拆成专项问题列表；复用非 ISSUE 结果的反馈主体和 revision 防覆盖。候选 API 的原有 COMPLETE 条件保留，扩展 Agent body 读取及比较集合，不把 taskId 为空的材料或其他项目材料混入。

## 7. 经实验确定的首版运行预算

负责人按 D-90 授权根据实验确定数值；以下作为首版默认值集中配置、发起时冻结。依据为数据库真实项目的取消链路、报告冻结及多提交调查，详见[实验记录](budget-calibration.md)。内网不设置货币花费上限，不以节约费用压缩调查；仍用调用、期限、上下文及无进展保护控制资源。这些值不是最大内网项目或完整模型窗口已验证的承诺。

| 项目 | 首版设计值 | 计量及检查位置 |
| --- | --- | --- |
| 模型轮次 | 48 | 最大最终样本为 30 轮，保留复杂任务及纠错余量；包括协议纠错轮次，下一轮前检查，已返回的最终提交仍允许在期限内发布 |
| 全部网络尝试 | 96，且不超过公共上限 200 | 复用 task_quota，首次与传输重试均原子预留；第 96 次已发响应可完成，禁止第 97 次 |
| 工具执行尝试 | 192；单轮最多 4 个普通工具 | 错误参数尝试也计入；逐次预留，完成最后一个允许的工具后禁止额外工具；submit_result 单独校验不消耗材料读取名额 |
| 任务期限 | 20 分钟 | 从创建开始，与公共 deadlineAt 取较早值；槽位等待、镜像准备和退避都计时；为内网及更复杂任务保留余量 |
| 单次模型超时 | 120 秒 | 与剩余期限取较小值；取消后不因网络仍返回而发布 |
| 输出预留 | 每轮 16384 token，不能超过模型声明 maxOutput | 实测最终回复超过 5000 token，留出复杂结论余量；16384 参数已用数据库项目完成真实调用验证；实际截断不得发布 |
| 累计资源额度 | `网络尝试上限 × (floor(窗口×80%) + 输出预留)`；当前 DeepSeek 为 82103424 个保守 token 单位 | 作为总资源保险，不再设额外 100 万的费用式小门槛；预留／结算及未知 usage 规则保留，不能把失败算零 |
| 上下文终止阈值 | 输入估算达到窗口 80% 时停止 | 还必须通过公共 `I + O + S <= W`；S 沿用 max(1024, 10%W)；任一条件不满足即不发送 |
| 无进展保护 | 连续 3 轮完全相同的工具组合、参数与返回，且无新增材料时停止 | 第 2 轮重复先提示；忽略调用 ID、时间等易变元数据，比较固定版本、游标与内容哈希。正常分页、不同查询及有效格式纠错不计入 |

I 覆盖 system、要求、指导提示词、完整 assistant/tool 历史、所有 schema、必要提供方字段及封装。沿用 UTF-8 字节上界估算，不直接套用 P31.9 的 0.25–0.27 换算比例；tokenizer 如新增须单独验证。窗口和输出配置缺失时不发起 Agent。容量检查必须针对实际序列化请求，不能只累加工具正文。

累计额度与单次窗口分别检查；工具返回限量不等于丢弃历史。预留耗尽时保留原因，不通过重新计数、创建内部子任务、摘要或增加收尾调用继续。实际 usage 超出预留时记录异常并禁止新增调用；已在预算内预留的最后响应不会仅因次数恰好等于上限而丢弃有效结果。

资源额度原子预留仍按 `I+O`，有实际 usage 后结算，缺失时保留预留。窗口阈值约束单次实际请求，累计额度约束全部尝试，两者不能混用。本轮较小样本正常结算时未触及原 100 万门槛，最终 30 轮多提交样本则在正常结算和 usage 缺失回放下均超出；提高额度依据这些实际消耗及保守回放，不把累计字节估算错误地当作已花费 token。无进展停止记 `NO_PROGRESS_LIMIT`，已有过程按限制终止保存，不追加总结调用。

暂态模型错误按公共层最多额外 1 次；语法／未知工具／结果引用等协议错误最多额外 2 次纠错轮次，每次保留错误及原始返回，不另套专项重试循环。普通工具超时不在工具内部再次自动重试，返回有界错误供模型决定替代方案，后续工具尝试仍消耗预算；固定版本的确切无匹配不重试为错误。权限失效、固定版本不可用、存储失败及无法继续的关键步骤直接失败。

## 8. 持久化与读取接口

只设计新的增量迁移，正式实施时确认当前最高版本后添加，不改已执行迁移。本轮不运行 SQL。

- 复用 review_task、task_quota、model_call、material、call_material、review_result；Agent 不建立假的 task_target 或 execution_unit。
- 拟新增 `agent_run`，task_id 为主键，保存 turn_no、tool_attempts、额度预留／结算、当前动作、已查覆盖及 revision；用于进度与重启收敛，不表示支持恢复。
- 拟新增 `agent_tool_call`，保存 task_id、model_call_id、turn_no、ordinal、provider_tool_call_id、工具名、参数、envelope、materialIds、开始结束时间和状态。唯一键 `(task_id, turn_no, ordinal)`；provider ID 在同一响应内必须唯一，不能假定跨轮唯一。
- model_call 增加 nullable turn_no；Agent 调用索引 `(task_id, turn_no, attempt)`。实际模型原始请求／返回、每次尝试仍独立保存。
- 工具返回先保存，下一次模型请求实际发送时追加 call_material 的 SENT 关联；未送入模型的材料显示「已取得，尚未发送」，取消或超限后仍可追溯。
- 完整结果发布新增 Agent 条件唯一约束或同任务原子发布闸门，禁止重复完整结果；失败事务不能留下可选材结果。

公共任务列表、详情、取消、结果和实际调用端点继续复用。拟增补以下端点，不向前端暴露可任意执行 Agent 工具的入口：

| 接口 | 返回／错误处理 |
| --- | --- |
| `POST /api/v2/agent-tasks` | 异步创建，校验及幂等冲突按公共错误约定 |
| `GET /api/v2/agent-tasks/{id}/progress` | 动作、轮次／尝试／额度、已查路径与比较覆盖、停止原因；仅本任务读取 |
| `GET /api/v2/agent-tasks/{id}/tool-calls?pageNum=&pageSize=` | 页码列表，默认 20、上限 100；不把大量正文放进列表 |
| `GET /api/v2/agent-tasks/{id}/tool-calls/{callId}` | 实际参数与返回，校验所属任务，读取失败可重试 |
| `GET /api/v2/agent-tasks/{id}/copy-input` | 可编辑原参数；重新解析版本、模型及提示词，不继承消息和额度 |

调用阅读支持轮次与尝试，结果、材料、调用分别加载及重试，沿用前端 epoch 防迟到响应。轮询 2 秒，终态停止、隐藏标签降频或暂停；取消失败保留状态及可重试提示，按钮防重复。新任务提交失败保留输入并复用幂等键，已成功创建后的重复响应不能创建第二份任务。
