# PAR 后续改造指南

本指南在 PAR-02 时编写，供后续 Agent 接续 PAR-03–05；只在负责人启动相应工作后实施。第 2 节已按原样抽取完成，见[模板抽取记录](par-03-templates.md)；PAR-04 已按第 3 节完成，见[边界收敛记录](par-04-convergence.md)；PAR-05 按第 4 节执行。先读工作区 AGENTS、STATE、ROADMAP、本目录计划、baseline.md 及对应记录。

## 1. 建立起点

核对分支与未提交内容，保存本轮生产源码基线提交 df48cac550fff9983b7be89276c5ce4eb729eaaa。运行 baseline.md 中的测试命令。固定 JSON 来自该提交未改造的生产实现，禁止通过重新捕获让修改后的实现自动通过。

## 2. PAR-03：原样抽取

1. 按 baseline.md 清单逐项迁移 PromptPurpose、SpecialistProtocol、PromptAssemblyService 中的静态文字。先迁移一个场景并验证，再迁移下一个。
2. 资源放在应用 classpath 中，使用 UTF-8；以清单声明用途、资源路径、版本及允许变量。变量只做明确替换，不解释脚本，不递归渲染材料中的占位符。
3. 保留 Java 文本块处理后的实际字符串，包括末尾换行。资源文件不能无条件 strip 或自动追加换行。
4. 场景选择、材料结构、行号、截断、历史回放及计量先保持现有逻辑。不要因为抽取而调整段落优先级、角色或材料位置。
5. 增加缺失资源、缺少变量、未知变量和打包资源读取检查。标识不要进入模型正文。
6. 每批运行固定请求基线及相关既有测试。差异须逐项解释，首轮不接受文案优化造成的变化。

## 3. PAR-04：职责收敛

将 AgentTaskWorker 的四类纠正消息转为类型化事件，触发条件、计数、插入位置及消息角色保持原样。非法批次还会产生逐工具失败结果，不能只移动最后一条 user 文案而遗漏 envelope 内的相同诊断。

工具描述提供层返回中立的能力定义，模型协议适配层生成当前工具 JSON。参数约束仍与 ToolArgumentParser 使用同一来源；名称、必填项、枚举、默认值及未知字段处理不变。工具示例、参数说明、返回诊断及 submit_result 纠错说明分别核对，不能仅搜索多行文本块。

保留后续按任务注入能力集合和指导内容的入口，不实现插件发现、导入、执行、MCP 或授权。公共规则与代码场景规则可以分开维护，但本轮生成结果必须等价。不得削弱固定版本、只读或证据引用要求。

## 4. PAR-05：验证与交付

固定 JSON 比较对象键值、数组顺序及所有字符串，不以对象键排列作为业务差异；完整模型请求、工具 Schema 与计量均须一致。既有执行测试覆盖取消、迟到响应、预算、非法批次、纠错耗尽、重复无进展、分片和发布。对本轮新增抽象补充必要边界测试。

最终执行后端回归及打包资源检查。真实模型验证单独安排并记录对象和调用结果，不保证随机输出逐字一致。没有实际运行的项目列为未验证。保持历史请求直接读取，不能用当前模板重新生成旧记录。

交付记录列出修改、验证、未验证项和部署边界；代码及资源一起发布或回退。不要增加热更新、数据库迁移或在线版本管理。同步 STATE、ROADMAP 及计划状态，不自动启动插件工作包。
