日期：2026-11-01。状态：BRC-01 done（三档复审调整完成），BRC-02／03／04 todo。基于 dev `146139f` 的静态检查；业务语义以[业务契约](../agent-redesign/business-contract.md)为准，前后端一致性通过该契约及相关接口文档约束。

## 1. 范围与规模

目标是减少同一后端规则在提示词、结构定义和校验代码中的独立维护，使修改规则时有明确的权威入口。本次属于局部、跨若干类的维护性重构，规模中等偏小：原范围涉及专项协议、Agent 提交、报告引用及两项公共辅助逻辑，初步估算约 15–25 个生产代码或资源文件，另有相关测试。2026-11-01 三档复审补入 BRC-04 的只读工具规则维护，并增加维护关联与兼容差异检查；原估算不覆盖新增工作，也不是文件数量限制。

输出契约是主要工作量，不能仅提取常量就认定完成；但无需新增业务模块、数据库表、API 或运行依赖。不设大型阶段里程碑，使用四个可独立审阅的小任务，测试并入各任务。验收以相关测试和最终后端全量回归通过为准，不要求真实模型调用、服务启停、数据库操作、页面视觉或部署验收。

不改前端，不生成跨语言类型，不建设通用规则引擎、配置语言、插件框架或在线契约管理。不重写执行循环、任务状态机、容量算法和历史记录读取。

## 3. 实施设计

### 3.1 按三档维护输出契约

规则按其含义分档，不按文件、语言或文本长度分档；一句说明可同时包含三档内容。Java 中存在中文、说明与校验位于不同类，不单独作为缺陷依据。

| 档位 | 内容 | 实施要求 |
| --- | --- | --- |
| 第一档：共同声明 | 字段、类型、枚举、必填、null／空数组、未知字段、长度／数量、引用格式；已向模型说明的默认值与限额 | Schema、结构校验及明示的数字／枚举／格式读取共同声明。保留历史场景差异，不因数值相等而合并含义不同的规则 |
| 第二档：语义一致与维护关联 | 材料发送资格、真实范围、目标／辅助角色、差异侧、依赖事实集合、版本权限、游标查询绑定、执行条件 | 保留清晰的业务校验入口、正反例及关联注释；在维护索引记录模型说明、诊断和测试位置。不要求从校验自动生成自然语言，不为共置说明而搬迁整段逻辑 |
| 第三档：自然语言指导 | 分析方法、优先级说明、质量与表达要求、段落组织、解释性示例 | 保留可读的模板或工具说明。示例须通过真实解析与相关业务校验；分析效果不以程序校验通过替代 |

具体入口、关联位置和改动触发条件见[维护索引](maintenance-map.md)。该索引仅记录位置与检查方式，业务事实以[业务契约](../agent-redesign/business-contract.md)为准。

输出结构继续使用轻量 Java 声明、现有模板和现有结果 record，不建设通用规则引擎、条件配置语言或第二套 DTO。必填数组和 null 元素在映射归一化前检查；显式映射的字段保持载体一致性检查。

模型看到的格式示例并非完整 JSON Schema，不必为了展示所有属性新增协议文字；已有明示约束从声明读取，新增约束时需核对是否要补充说明。第一档只共用可证明相同的规则：证据数组总数与其中目标依据数、诊断展开上限与引用数组上限分别维护。

专项：文件／差异结构共用；changeRelation、材料侧及角色属于第二档。数量声明保留，目标资格判断由 SpecialistResultValidator 负责。场景说明保留在协议或 instruction，不借契约回调生成业务段落。

Agent：工具定义与 AgentSubmission.parse 共用结构。状态名、引用格式、最低数量从共同声明取得；发送材料集合、行范围、正文引用解析、裁剪与多错误诊断由 AgentSubmission.validate 负责。自然语言说明通过维护关联与业务测试保持一致，不为状态文案建立参数化执行规则对象。

报告：保留轻量引用格式、最低引用数及范围校验。来源冻结和资格属于第二档，事实保真及写作指导保留自然语言，不引入专项 JSON 结构。

### 3.2 提示词版本解析

抽取可跨 service／report 使用的基础版本解析：版本存在、归属正确、正文非空。专项和 Agent 仅在版本 ID 为 null 时使用当前版本；显式空白或无效版本不得回退。报告允许不选通用规则（提示词与版本 ID 均为 null）；一旦选择，二者必须同时显式提供，空白值不算未选。将这些策略留在入口或显式参数中，不能让报告隐式回退当前版本。保留既有错误码和对外诊断语义，避免统一辅助类后改变失败分类。尤其保留版本正文为空时专项／Agent 的 CONFIG_INCOMPLETE 与报告的 VALIDATION_FAILED，不把调用场景差异硬塞入统一默认策略。

### 3.3 模型快照

提取三类入口共同的模型快照构造逻辑。保留每个场景的外层快照结构、字段顺序、字段存在性、null 表达、默认协议和版本字段；确有差异时显式表示，不用统一默认值覆盖。凭据仍不写入快照；不改历史快照、不新增快照迁移。此项不顺带统一各场景模型准入要求。

### 3.4 五类只读工具（BRC-04，新增计划）

本项补上原计划遗漏，当前只做规划，暂不实施。审阅 tree、find_files、search_code、read_code、read_diff：

- 第一档：核对 ToolParameter 的声明、工具 Schema 与实际执行限额；优先处理默认起始行、默认读取范围、版本／比较标识长度和模式、条目／行数／字节上限。证明同义后再共用，保留 parserDefault 与执行默认等已知差异。
- 第二档：路径、单行字面量查询、游标查询绑定、零命中／截断、版本权限及批次约束只明确权威实现、相关说明与正反例；不要求生成全部语义说明。已有事件参数驱动的批次数量提示继续复用。
- 第三档：用途、查询示例、调查建议及结果解读保留可读文本。工具名、明示数量和格式可插值，其余说明不做机械拆分。
- 复用现有工具／执行器测试和工具请求基线；不改检索算法、工具行为、限额值或执行循环。发现说明与实际行为冲突时，列出输入与两端结果，再按兼容原则处理。
