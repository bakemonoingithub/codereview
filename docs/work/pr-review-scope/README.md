## 1. 目标与非目标

目标是在已有项目中手工选择待合并 PR，并以发起时冻结的 PR 净变化作为问题专项或 Agent 的审查范围。GitHub 验证仓库与 Gitea 1.16.1 内网仓库使用同一业务语义；结果、代码证据、材料和报告来源能说明固定版本与未覆盖范围。现有文件／提交审查、反馈、统计、报告、取消和历史阅读保持可用。

本工作包不建设 PR Webhook 自动触发、评论或状态回写、自动合并拦截、SonarQube／Jenkins／单测门禁，也不验证合并后代码的编译或集成冲突。目标分支移动时显示受影响 PR 的版本提示，由用户决定是否重审。

## 2. 待实施接口及决定点

| 对象 | 拟用的新增读取能力 | 用途与边界 |
| --- | --- | --- |
| Gitea 1.16.1 | `GET /repos/{owner}/{repo}/pulls`、`GET /repos/{owner}/{repo}/pulls/{index}` | PR 列表与详情；不假设该版本存在 `/pulls/{index}/files`。 |
| GitHub | `GET /repos/{owner}/{repo}/pulls`、`GET /repos/{owner}/{repo}/pulls/{pull_number}` | PR 列表与详情；复用现有项目凭据和 GitHub 宿主路由。 |
| GitHub，候选 | `GET /repos/{owner}/{repo}/pulls/{pull_number}/files` | 若选为文件清单来源，须处理分页和 3000 文件上限；达到上限不能宣称清单完整。 |
| Gitea，候选 | `GET /repos/{owner}/{repo}/pulls/{index}.diff` | 仅在固定 SHA 镜像比较无法覆盖目标样本时再评估，不作为默认实现。 |
| 本系统 | 项目下 PR 列表、详情、固定净变化清单及前后材料的只读接口 | 供选择器、预览与审查任务使用；路径与错误契约在 PRS-01 定稿，不在本计划臆造 URL。 |

优先复用当前 GitHub／Gitea 凭据配置、`GitHostClientRegistry`、固定 SHA 文件读取和共享 Git 镜像。PRS-01 必须对比 GitHub PR 文件接口与固定 SHA 比较、Gitea 本地镜像与 PR diff 的完整性和版本一致性，再选定每种宿主的材料路径。跨仓库 PR、无共同祖先、目标或源版本不可读、重命名／删除、纯二进制、混合不可读内容、超大 PR 的处理规则也在该步固定；不默认为已支持。

## 4. 分步实施要点

### PRS-01：可执行设计与基线

1. 核对 `dev`、HEAD、工作区原有修改和当前可运行的测试入口；冻结现有单提交与多提交行为样本，避免 PR 改造改变旧语义。
2. 固定 PR 标识、目标仓库、源／目标分支及 SHA、共同祖先、净变化文件清单、版本移动检测和复制参数重取版本的字段；决定同仓库与 fork PR 的首版边界。
3. 对 GitHub、Gitea 分别形成新增接口清单、权限与分页说明，确定固定比较材料的权威来源及完整性检查；接口新增范围在代码实施前向负责人清楚展示。
4. 固定专项默认选中文本文件的行为、部分选择、纯二进制与混合不可读结果的状态、未覆盖计数与报告候选资格；用真实仓库样本检验，不以文件扩展名或 patch 缺失判断二进制。
5. 固定前后侧角色与证据引用：`BEFORE` 为共同祖先，`AFTER` 为源提交，目标分支版本另行标识；检查现有结果和报告 Schema 是否需要扩展，避免先改数据库后发现来源含义不够。

### PRS-02：共享 PR 来源与材料

先接入宿主 PR 元数据和只读列表／详情，再提供按固定 SHA 的净差异文件与两侧材料。创建任务时复核源／目标版本，变化则明确失败并要求刷新；任务接受后只用冻结版本。文件清单若被截断或超限，不能以部分清单继续声称完整。重命名、删除、二进制、文本编码、不可读和镜像缺失分别分类。现有 `/commit`、`/diff` 及单提交结果继续保持原语义。

### PRS-03／04：两条执行路线

专项每个选中文本文件仍为一个目标，可延用现有智能拆分与有限声明增强；PR 中多次修改同一文件只按净变化生成一个目标。Agent 只获得冻结版本和一个 PR 比较关系；修改 `read_diff` 的文件清单与逐 hunk 读取来源，不能仅修改提示词。两条路线均通过统一提示词组装，按三档维护标准核对说明、工具参数、结果校验、维护索引和既有固定请求／工具基线。模型输出的发现仍需人工判断，不据此生成质量门禁结论。

### PRS-05：正式前端与报告

按[前端复用清单](assessment.md#23-当前前端的复用与新增清单)在 `ReviewLaunch.vue`、`AgentLaunch.vue` 增加 PR 模式，新增 PR 选择器和必要的变更文件选择界面。专项详情沿用左侧目标文件与右侧三页签；Agent 详情沿用进度、结果、输入与实际调用。`MaterialReaderModal` 的现有差异按钮使用单提交 `/diff`，PR 模式须改用固定比较材料或隐藏，不能显示第一父差异。报告候选、事实和冻结来源按 PR 版本说明，不改变既有历史报告。

### PRS-06：验收矩阵

至少覆盖：多提交但只有一个净变化文件、同一文件多次修改后抵消、目标分支独有提交、源／目标移动、重命名与删除、纯二进制、文本与二进制混合、文件清单超限／不可读、取消与迟到结果、报告冻结后 PR 再更新、复制参数重新观察版本，以及现有文件／单提交／多提交范围回归。GitHub 与 Gitea 分开记录实际样本和运行环境；服务、数据库、真实模型及视觉验收各自留证。缺少某一目标环境时保留对应未验证项，不以另一宿主替代。
