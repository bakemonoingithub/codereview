## 三、需要开的防火墙端口（**请注意方式**）

应用需要从内网访问目标机的 **18080**。若目标机 firewalld 处于运行状态，请按下面这样开：

```bash
# 先确认状态
systemctl is-active firewalld
firewall-cmd --state

# 若 firewalld 在运行：
firewall-cmd --permanent --add-port=18080/tcp   # 持久化（不触发 reload）
firewall-cmd --add-port=18080/tcp               # 运行时立即生效
```

> ⚠️ **请勿使用 `firewall-cmd --reload`。**
> Docker 20.10（以及 < 28.0.0 的所有版本）存在 **CVE-2025-54410**：firewalld reload 会重建规则并破坏 Docker 的容器网络隔离，任意容器可访问其它容器的端口。官方修复方式是重启 Docker —— 但**这台机器上重启 Docker 会连带重启 Dify、ITSM 等 20 多个容器**。上面的写法（运行时添加 + 持久化添加，不 reload）可以避开这个陷阱。

## 四、明确不会做的事

本套部署脚本**不含**以下操作，请放心：

- ❌ `docker system prune` / `docker container prune` / `docker volume prune` / `docker image prune`
- ❌ `systemctl restart docker`（不重启 Docker 守护进程）
- ❌ 修改防火墙规则
- ❌ 停止、删除、重建本项目以外的任何容器 / 网络 / 卷 / 镜像
- ❌ 修改系统内核参数、SELinux、yum 源

所有改动都局限在：部署包目录 + `codereview` 这个 compose 项目。

## 六、回滚

```bash
cd <部署包目录>
bash scripts/rollback.sh
```

机制：每次部署前，脚本会把当前运行版本另打一个 `codereview-app:previous` 标签；部署后如果健康检查 5 分钟内没通过，**脚本会自动切回 `previous` 并重启**，无需人工介入。
回滚目标始终是"上一次成功部署的版本"，不依赖网络（镜像已在本地）。

---

## 七、完全卸载（含数据）

```bash
cd <部署包目录>
docker compose -p codereview down            # 停容器 + 删本项目的网络
docker rmi codereview-app:latest codereview-app:previous mysql:8.0.36
rm -rf <部署包目录>                           # 连同 data/ 一起删除，数据不可恢复
```

`down` 只影响 `codereview` 项目，不会碰其它项目。
