## 三、需要开的防火墙端口

应用需要从内网访问目标机的 **18080**。

系统室应该有规定，哪些端口范围是允许开放的

如果18080端口允许开放，则直接申请防火墙端口即可

如果18080端口不允许开放，则需要修改`.env.example`中的APP_PORT端口号

## 五、回滚

```bash
cd <部署包目录>
bash scripts/rollback.sh
```

机制：每次部署前，脚本会把当前运行版本另打一个 `codereview-app:previous` 标签；部署后如果健康检查 5 分钟内没通过，**脚本会自动切回 `previous` 并重启**，无需人工介入。
回滚目标始终是"上一次成功部署的版本"，不依赖网络（镜像已在本地）。

---

## 六、完全卸载（含数据）

```bash
cd <部署包目录>
docker compose -p codereview down            # 停容器 + 删本项目的网络
docker rmi codereview-app:latest codereview-app:previous mysql:8.0.36
rm -rf <部署包目录>                           # 连同 data/ 一起删除，数据不可恢复
```

`down` 只影响 `codereview` 项目，不会碰其它项目。

## 八、其他命令

```bash
cd /opt/codereview-offline-<版本>

# 看状态
docker compose -p codereview ps

# 看应用日志（实时）
docker compose -p codereview logs -f codereview-app

# 重新部署一个更新包（把新包解压后，把 images/ 和 scripts/ 覆盖过来，然后）
bash scripts/deploy.sh

# 回滚到上一版本
bash scripts/rollback.sh

# 手工备份数据库
bash scripts/backup.sh

# 启动/停止服务
docker start/stop codereview-app/codereview-mysql
```

**每日自动备份**（可选，建议加上）：`crontab -e`，加一行

```
0 2 * * * cd /opt/codereview-offline-<版本> && bash scripts/backup.sh >> backups/backup.log 2>&1
```
