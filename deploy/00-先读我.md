# 内网部署操作

## 0. 前提

- 目标机：CentOS 7.6，已装 Docker 20.10.24 + Compose v2.17.2
- 用 root 或 docker 组内的账号执行
- U 盘里的 `codereview-offline-<版本>.tar.gz` 已拷到目标机（例如 `/opt`）

---

## 1. 解压

```bash
cd /opt
tar xzf codereview-offline-<版本>.tar.gz
cd codereview-offline-<版本>
```

## 2. 先体检（只读，不改任何东西；约 10 秒）

```bash
bash env-check.sh
```

看到一堆 `[xxx]` 分组输出就对了。**记录最后是否有明显的错误信息**。
体检只读，跑坏不了东西，可以随便重跑。

## 3. 校验镜像包完整性（可选，约 1 分钟）

```bash
cd images && sha256sum -c SHA256SUMS.txt && cd ..
```

两行都显示 `OK` 就说明 U 盘拷贝没损坏。**如果显示 FAILED，先重新拷一遍**，别往下走。

## 4. 部署（核心步骤，约 3~5 分钟）

```bash
bash scripts/deploy.sh
```

脚本会自动做这些事，中间只有一次 `[y/N]` 确认：

1. 生成 `.env`（自动创建两个随机数据库密码，并打印在最后，**请抄下来**）
2. 生成 `config/application.yml`（把数据库密码、AI 网关地址填进模板）
3. 前置体检：磁盘空间、内存、端口 18080、Docker 状态 —— **任何一条不过就中止，不会乱动系统**
4. 装载两个镜像包
5. 备份数据库（首次部署没有库，自动跳过）
6. 启动容器
7. 等健康检查通过（最多 5 分钟）

**首次部署时询问，直接输入 `y` 回车。**

## 5. 看结果

成功会打印：

```
[ OK ] 部署完成 —— 访问地址： http://<本机IP>:18080
```

浏览器打开这个地址，应该能看到系统页面（左侧有「项目 / 审查记录 / 策略 / 提示词 / 模型配置」等菜单）。

## 6. 出错怎么办

**情况 A：脚本自己打印了「自动回滚」，最后提示"已回滚到上一版本"**
→ 说明新版本有问题，系统已经自己退回上一版，业务没受影响。把屏幕输出截图给开发即可。

**情况 B：脚本在中途报 `[错误]` 并停住**
→ 它没做任何破坏性动作，按报错文字处理即可，常见三类：

| 报错关键词 | 处理 |
|---|---|
| `端口 18080 已被占用` | 编辑 `.env`，把 `APP_PORT` 改成别的空闲端口，重跑 |
| `可用空间仅 xG` | 清一下目标机磁盘（**只清自己的**，别动 Dify/ITSM 的镜像），重跑 |
| `Docker 守护进程不可访问` | 换 root 执行，或让用户加入 docker 组 |

**情况 C：脚本卡在"等待容器 healthy"最后超时**
→ 脚本会自动打印最近 60 行日志。把这部分一起给开发。

## 7. 日常操作速查

```bash
cd /opt/codereview-offline-<版本>

# 看状态
docker compose -p codereview ps

# 看应用日志（实时）
docker compose -p codereview logs -f codereview-app

# 重新部署一个更新包（把新包解压后，把 images/ 和 scripts/ 覆盖过来，然后）
bash scripts/deploy.sh

# 回滚到上一版本
bash scripts/rollback.sh

# 手工备份数据库
bash scripts/backup.sh
```

**每日自动备份**（可选，建议加上）：`crontab -e`，加一行

```
0 2 * * * cd /opt/codereview-offline-<版本> && bash scripts/backup.sh >> backups/backup.log 2>&1
```

## 8. ⚠️ 这台机器上还跑着别的系统，请务必不要做

这台机器同时运行着 **Dify、ITSM、onlyoffice、ai-fomart** 等 20 多个容器。以下命令**会波及它们**：

| 不要执行 | 原因 |
|---|---|
| `docker system prune` / `docker volume prune` | 会删掉别人的镜像和数据卷 |
| `systemctl restart docker` | 会把这 20 多个服务全部重启 |
| `firewall-cmd --reload` | 在 Docker 20.10 上会破坏容器间网络隔离（CVE-2025-54410），且必须重启 Docker 才能修 |
| `docker compose down`（在别的目录执行） | 会停掉别人的服务 |

本套脚本只会操作名为 `codereview` 的 compose 项目，以及 `codereview-app` / `codereview-mysql` 两个容器。

---

## 9. 需要交给开发的信息

出问题时，把这三样发过来，基本就能定位：

1. 报错前后的完整屏幕输出（或 `backups/` 旁边那份体检报告）
2. `docker compose -p codereview logs --tail=200 codereview-app`
3. `docker compose -p codereview ps`
